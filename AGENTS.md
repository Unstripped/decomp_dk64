# AGENTS.md

Matching decompilation of Donkey Kong 64 (USA). Status, ROM map and remaining work: `ROADMAP.md`.

## Hard rules

- **Never commit game data.** No ROMs (`*.z64`, `*.n64`, `*.v64`), extracted binaries (`bin/`, `assets/`), or generated asm (`asm/`). All are gitignored and regenerated by `make setup` from the user's own ROM. History was rewritten once to remove a ROM; do not reintroduce one.
- **The build must stay matching.** `tools/dk make` must end with `build/dk64.us.z64: OK` (the global and overlay text/data hashes are checked just before it; any FAILED line stops the build). Never commit a non-matching state.
- Run every build tool inside the container (`tools/dk <cmd>`); the host has no MIPS toolchain.

## Build

```sh
docker build -t dk64-decomp .          # after Dockerfile/requirements.txt changes
tools/dk make setup                    # extract + split (BASEROM=donkey-kong.n64)
tools/dk make                          # build + SHA-1 check
tools/dk make split                    # re-run splat after yaml / symbol changes
```

`make split` deletes and regenerates `asm/` and `assets/` (both splat configs); it never overwrites existing `src/*.c`.

## Layout

| Path | Purpose |
|---|---|
| `dk64.us.yaml` | splat config for ROM `0x0`–`0x113F0`: header, entry, boot, rspboot (segments, file splits); `build/dk64.us.elf` is the boot ELF |
| `dk64.global.us.yaml` | splat config for the decompressed global segment (`bin/segments/global.bin`, VRAM `0x805FB300`); outputs `asm/global`, `src/global`, `build/global.elf` (links against boot via `--just-symbols`) |
| `dk64.<overlay>.us.yaml` | one splat config per overlay (`multiplayer minecart bonus race critter boss arcade jetpac menu`, all VRAM `0x80024000`; source stream `bin/segments/ovlNN.bin`); outputs `asm/<overlay>`, `build/<overlay>.elf` (links against global + boot via `--just-symbols`). Overlay list, stream ids and text sizes: `OVERLAYS` in `Makefile` |
| `*.sha1` | expected hashes: full ROM, global and per-overlay text + data |
| `symbol_addrs.us.txt` | boot + global names; add names here, not by editing asm |
| `symbol_addrs.<overlay>.us.txt` | overlay-local names (overlay addresses collide, so never put them in `symbol_addrs.us.txt`) |
| `undefined_syms.us.txt` | symbols outside any segment (libultra low-memory globals) |
| `tools/extract.py` | ROM → `baserom.us.z64`, `bin/segments/*` (inflated code streams, raw pieces, `table12.bin` + `assets.bin` ROM tail), `bin/layout.json` |
| `tools/compress.py` | packs built text + data into a ROM segment: GNU gzip 1.2.4 `-9 -n` members (the only compressor that reproduces all 20), zero-padded to the segment size. The ROM is `build/boot.bin` + 10 compressed segments + raw tail (`Makefile`, `ROM_SEGMENTS`) |
| `src/` | C sources; `#pragma GLOBAL_ASM(...)` for unmatched functions |
| `include/` | headers; `ultra64.h` is a minimal libultra subset, extend as needed |

## Decompiling a function

1. Convert its file to C in the segment's splat config (`dk64.us.yaml`, `dk64.global.us.yaml` or `dk64.<overlay>.us.yaml`: `[0xOFFSET, c, dir/name]`), then `tools/dk make split`.
2. Replace the function's `#pragma GLOBAL_ASM("asm/.../nonmatchings/...")` line with C.
3. `tools/dk make`; on mismatch, compare with `mips-linux-gnu-objdump -d` on the segment's ELF (`build/dk64.us.elf`, `build/global.elf`, `build/<overlay>.elf`) against `asm/.../nonmatchings/...`.
4. Name the function and any discovered symbols in `symbol_addrs.us.txt` (boot/global) or `symbol_addrs.<overlay>.us.txt`.

Compiler notes:
- IDO 5.3 `-O2 -mips2`. libultra objects may need different flags; check before forcing C to match.
- `while (cond) {}` compiles to a rotated loop with `beqzl`; the original often uses `do {} while (cond);`.
- asm-processor needs `/opt/asm-processor/prelude.inc` (sets `noreorder`). splat's `nonmatching` macro is disabled because asm-processor miscounts its lines.

## Conventions

- Unidentified symbols keep splat names (`func_XXXXXXXX`, `D_XXXXXXXX`) until their behaviour is confirmed.
- File splits: follow splat's suggestions, but check data/rodata boundaries against 16-byte alignment and string placement (boot rodata is `0x10F60`, not splat's `0x10F74`).
- Update `ROADMAP.md` checkboxes when a step lands.
