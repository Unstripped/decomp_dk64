Hackvsprintf12 (ledger 778fd04d), boot/3D20 vsprintf e-arm zero pad. With the dead-test trio removed, the down-counter `for (d = width - elen; d-- > 0;) PUTC(padChar);` matches every register in the function (Hackvsprintf11, score 5); only the loop at 0xb9c-0xbb8 differs (subu v1,t0,a1 / blez / slt v1,zero,v0 against the target's slt v1,a1,t0 / beqz / addiu t0,t0,-1, an `elen < width` test that decrements width). Adding `width--` to the step gives 7: uopt keeps both d and width as loop counters (an extra addiu t0,t0,-1 at 0xbc0) and does not rewrite the exit test onto width, so the target's test cannot come from a down-counter on a second variable. The forms with the target's test leave d unused and uopt deletes it (154), so they cannot keep d live in v0 across the loop either.
