In HackarcadeUpdateDonkeyKongStage3 (merge 847de629), arcadeSpawnStage1Entities 6ec87d was kept. The target emits `li v1,36` at 0x41b4 and then `addiu v1,v1,-1` once per entity. An `i = 0x24` definition placed before the D_8004A76C/D_8004A740 block was tried at five positions: at entry and after each of spawns 1, 2, 3 and 4. Every placement keeps the index in `v1` but swaps `a0`/`a2`, giving full=122 each time. So moving the constant def does not fix the colouring order, unlike the Q0252 dead-assignment lever. Only an early `i = 0` def plus `i + 0x24` after the join reproduces the target order. The early dead def sets the candidate's first-appearance position, and the add after the join supplies the 36. Rewriting the four entity spawns as a `for (j < 4)` loop is not unrolled by IDO and scores 383, so keep the spawns written out. Unit "2026-11-15: cleanup HackarcadeUpdateDonkeyKongStage3".
