A splat label that points into the middle of a struct array is not a separate object. Defining it as its own array changes the layout: IDO aligns a separate array of 8-byte-aligned structs to 8, so it lands at the next 8-byte boundary instead of directly after the previous elements. Carve the whole array as one definition.

Evidence: arcade/0.c: D_8004BCAC lies inside `ArcadeLift D_8004BC88[6]`; defining it as its own `ArcadeLift[3]` placed it at +0x30 instead of +0x2C, so the carve uses the single 72-byte array.
