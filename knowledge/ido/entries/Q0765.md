When the target keeps a scalar counted loop (`slt` with the bound in a register) over a constant trip count, every literal spelling of the bound is unrolled, and the spellings that avoid the unroll change the loop test instead. Keep the bound in a local (`limit = 13`): uopt keeps it a vreg (`ules i, limit`) that becomes `li` only at register allocation, so it is a legitimate form, not a FAKE.

Evidence: particleFindPathIndices (global/699B0.c, `limit = 13` kept; target `slt` at 0x5c): a 13-trip walk over 0x20-byte structs whose body has a global read-modify-write unrolls (70 insns, iteration 0 peeled) with a literal bound written as for/while/do-while, `<= 12`, `!= 13` or `(u32)`; `for(;;)` + break gives `bne`, an end-pointer bound gives `sltu` via LFTR, and a sizeof bound folds back to the literal.
