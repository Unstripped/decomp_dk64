`c = cmd->c; c &= 0xFF; c &= 0x7F;` (a redundant double mask) keeps `move a2,v0; andi t5,a2,0x7f; move a2,t5`; a single `&= 0x7F` is folded. `i = 0; for (; i < n; i++)` gave the actor loops' cursor `$v0` / count `$v1` / `i` `$t0`, and separate pointer/index locals per loop group change their colouring (`csCmdExec`, `csCondEval`).

**2026-11-17 correction (Polishglobal42630 b264b7a5, HackcsCmdExec3 aa3c1dc7):** (1) the `i = 0; for (; ...)` effect is as1 line-order scheduling, not register allocation: the init on its own line puts `move t0,zero` ahead of the gActiveActors address (csCmdExec 0x23f4, 0x3664); on the for line (or one line with it) it lands after. (2) The `c &= 0x7F` double mask was u8 narrowing written by hand: `x & MASK` (MASK < 0xFF) from an s16 field into a u8 local gives `move rV,rX; andi rT,rV,MASK; move rV,rT` (the narrowing is the second mask); into an s32 it folds to one andi. An s32 callee prototype where the real one is u8 can hide this: try the real narrow local width and the shared prototype together (0x2fd4-0x2ffc, 0x301c-0x3028, 0x30a4-0x30f8, 0x317c-0x31a4).
