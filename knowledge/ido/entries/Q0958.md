This is `func_8068EF54` in the HackcollisionTestActorBoxFloor2 cleanup unit (2026-11-15, commit fa33ae, kept). Wrapping a ternary in a comma expression sends it through cfe's shared f64 ternary temp (M-208, candidate 86). It also adds a `ustr` into `ratio` (candidate 90). Together these shift the numbers of all later FP candidates by 3. Because of that shift, a distant FP constant (the `lightAdd` `0.0f`) is coloured to `$f16`. Once `$f16` is a coloured web, ugen drops it from the FP scratch ring for the whole function. The result is the target's `mul.d $f18,$f8,$f10` at 0x81c. Without the wrapper, the code gets `mul.d $f16` plus an early `ldc1 $f6` at 0x814 (full=106). Candidate numbering from cfe temps therefore decides which register a far-away constant gets. Through ring membership (Q0442), that choice changes scratch register names in unrelated FP arithmetic. This is a different lever from the FIFO-order effect in Q0560 and the operand-order wrappers in Q0434.
