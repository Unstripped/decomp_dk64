Pointer induction variables that uopt derives from an index are advanced by ugen at the statement incrementing the index, so a store placed after the increment uses a -1-element offset from the advanced pointer. That offset is part of source order (ugen emits it; as1 does not add it): place the increment where the target's offsets change.

Evidence: screenBlurApply (global/2DE90.c).

**2026-11-17f correction (CleanscreenBlurApply 4a8bee9e):** File src/global/2DE90.c, screenBlurApply 757606 (fixed). CORRECTS Q0797 (see Q0828, Q0460, Q0183, Q0483): a for-step `i++, idx++` takes the `for` line's `.loc` even when written on its own physical line; as1 hoists those pointer advances above the body's earlier byte stores and rewrites their offsets to -1, while an `idx++;` body statement stays after the stores (loop 1 0x13b8-0x13d0: for-step 0, body form 12; loops 2/3 plain-register idx: 0 vs 3). Q0797's "as1 does not add it" holds only for an increment written before the stores.
