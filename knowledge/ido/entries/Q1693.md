An index loop over a small global pointer table compiles to the target's separate end-address shape where a pointer walk ending at an explicit `&arr[N]` does not. In 11BC10 timedLightOrbitUpdate, `for (i = 0; i < 4; i++) if (effect == gRaceSparkEffects[i])` gives `lui v1` 0x3788 / `addiu v1,v1,16` 0x37ac (%lo gRaceSparkEffects+0x10, the end address as its own symbol+addend), the element cursor `lui v0` 0x3798 / `addiu v0` 0x37a8 and a `bnel v0,v1` latch at 0x3988 (uopt strength-reduces the index into the cursor and keeps the end as a separate constant). A hand-written walk `slot = arr; do { ... slot++; } while (slot != &arr[4]);` or `arr + 4` folds the end into the base register (one extra addiu from the cursor's base) and does not match. Before 9fb06572 the source matched only by ending the walk at a misdeclared neighbour symbol (`extern void *gLightSlotNext`, the race overlay's u8 that happens to sit at gRaceSparkEffects+0x10), which gave the end address its own relocation. Contrast Q1629: an ordered `sltu` address-compare exit is ORIG; this `bne`/`bnel` exit is the plain index form and is ordinary C.
