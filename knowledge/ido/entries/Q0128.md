declaring the return `int` instead of `s32` (`long`) flipped v0/v1 for a cached global pointer and removed an argument spill (`actorIsTargetInRange`, byte-identical only as `int`). The same holds for locals: in `menuUpdateLightFadeActor` an `int maxLevel = 0xFF;` limit local compared with `s32 cur` (`cur != maxLevel`) gives the target's `beq` operand order once the shared `u8` `lightAdd` prototype replaced a local `s32` one; `s32 maxLevel` (and `int cur`/`d`) do not.
