Extends Q1047/Q0941. For a `while (i-- > 0)` loop whose count comes from a quotient: if the target computes the quotient into an expression temp (t7/t5, used only by `blez` and the `addiu counter,-1` in its delay slot), the quotient was also stored to a named variable whose store copy propagation then leaves dead; a plain `i = q` gives i's first definition its own uopt range (v1 with `i = count / 4`); using the variable itself as the counter keeps the decremented value in that variable's register (s8), cannot reach the separate a3 counter, and turns the guard into `slt` + `beqz`. Evidence: global/100180 textDrawStringVtx 0x1554/0x1560 and 0x171c/0x1728; the count-as-counter body scores full 8 (exactly those 4 lines per site), so the tagged `i = count /= 4;` dead stores (cdb041, cdb041#2) stay.
