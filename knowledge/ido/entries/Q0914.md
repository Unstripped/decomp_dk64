In `csCmdExec` (src/global/42630.c, unit HackcsCmdExec2, ledger-only 70dac9ef, base 985cee76, commit 4f1968 kept), the unused escape `void *dm = &csId` does two things. It adds the frame word, and it aliases the parameter, so `csId` becomes a memory variable that is reloaded inside the case 0x2D actor loop (`lh t5,210(sp)` at 0x3694, feeding `bnel` at 0x36a4). An unused `s32 pad` declared where `dm` was reproduces only the word: `sel` lands at 179(sp) and every slot matches. But uopt then colours `csId` into a1 before the loop (`lh a1,210(sp)` at 0x3674), which scores full 100. A `u8` pad or no local at all scores 157. The target never forms `&csId` (there is no `addiu aN,sp,208`), so the escape produces no code. Rule: the pad lever (bonusControllerUpdate 7cc88e36) only works when the escaped variable is not reloaded through memory afterwards. Otherwise keep the real escape. Unit "2026-11-15: cleanup HackcsCmdExec2".

**2026-11-17 extension (HackcsCmdExec5, ledger 930ea5e6):** a K&R (old-style) definition with an s16 parameter leaves csCmdExec's code unchanged: the parameter does not become memory-resident, so a K&R rewrite cannot stand in for an `&param` escape (4f1968 `void *dm = &csId;`); it does change callers that lose the prototype (csStateUpdate) and .rodata.
