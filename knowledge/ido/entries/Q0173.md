`rodata_owners.py`'s pad after `D_80758920` left two 16-aligned starts (`func_80642940`, `func_80642BF0`); the earlier one reads the same bss trio (`D_807F621C`–`24`) as the first TU's functions and the later one reads `D_8071FF18` like the next function, so `0x478F0` was chosen, but globals can be shared across TUs so this ranks candidates rather than proving ownership. A data pad flagged after one nonzero float and two zero words (`D_807482A4`) is either a `{x, 0, 0}` triple or a scalar plus 8-byte TU padding; an all-`GLOBAL_ASM` matching gate cannot distinguish them (both link identically), so treat it as a possible third TU until a function in that range is matched and its data ownership settles it.
