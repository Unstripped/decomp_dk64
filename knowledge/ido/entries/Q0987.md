A compound assignment through a pointer deref is not interchangeable with the written-out form: `*p += e` loads `*p` first and then evaluates `e`, so the operand load order of the add changes. When the target evaluates the right-hand side before the field, keep the long form.

Evidence: camUpdateEyePos (global/201B0.c): the float ease `*p = *p + (g - *p) * k` (or `(g - *p) * k + *p`) matches, while `*p += (g - *p) * k` does not; the target adds `X*blend + field` in that order for `st->unk88`. For a plain struct field the same respelling is safe: camUpdateFollow's `st->unkE4 = st->unkE4 + ...` matches as `st->unkE4 += ...`.
