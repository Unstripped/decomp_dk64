This is the fourth case of Q0552. In playerInputUpdateCannonAim (global/E4090.c), sites e9a088, 9bdc6b, bdc230 and acd1db are fixed once `gButtonRemapTable`..`gPlayerInputHandlers[107][17]` are defined in the same TU (yaml `[0x155CF0, .data, E4090]`). One site, c17942, still needs a tagged `if (gCurrentActor) {}` at the jump-block head, so the fake guards go from 4 to 1. The table makes the function's entry label address-taken, which gives the switch `jr t4` at 0x4424 a false edge to the entry block and changes the XBB weights. playerTurnByStickX has no switch and is unaffected, which confirms that a switch is required (104F0 is also negative). The do-while(0)/dead-if explanation in Q0723 for this function should therefore point to Q0552. A table entry whose handler returns s32 in a `void(*)(void)` slot is written as `(void (*)(void))playerInputPostUpdate`, keeping the real return type, and gives no warning.
