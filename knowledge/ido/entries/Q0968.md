This came up in the HackschedDlDebugDump2 cleanup unit (2026-11-15). It extends Q0470. Q0470 shows that a `&G` call argument and a `G.field` read CSE into one pointerized `lda`. When the buffer is a struct member at a nonzero offset inside a containing struct, the shared address web breaks. With `osContGetReadData(&S.pad)` followed by `S.pad.button`, each access keeps its own `lui`: `lui a0` at 0xea0 and `lui v0` at 0xeac. This is the natural replacement for the fake spelling that builds the argument off a neighbouring symbol (`(u8 *)&D_807F0564 + 4`). The nonzero member offset seems to keep uopt from treating the call argument and the field read as the same base address. That offset-based mechanism is inferred, not confirmed. fdiff reports RELOC-EQUIV, with only the LO16 addends differing at 0xc98, 0xea8 and 0xeb0. Use this spelling in place of the neighbour-symbol trick when the data can be modelled as a containing struct.
