Both FAKEs FIXED by the N64 SDK amCreateAudioMgr shape: the cmdBuffers index loop reuses the same u32 i (declared first), and the SDK spellings `alHeapAlloc(...)` and `cmdCount * sizeof(Acmd)` are used. FAKE 2 -> 0; 6710 has 0 sites left. The director judged it ordinary (SDK idiom; i shared in the same loop-counter role). 1. EXTENDS Q1224/Q0849 (uopt loop): a later loop on the same counter blocks LFTR. A counted loop whose counter is read after the loop (`sAudioDmaBuffers[i].ptr` for the last element) and then reset by the next loop's `i = 0` in the same exit block keeps its counter and the sltiu exit (0x124). uopt does neither EQ_INEQ nor LFTR there. Both conditions are needed: - a separate counter j for the next loop gives LFTR (score 64); - a pointer walk as the next loop gives LFTR (62); - not reading i after the loop (`sAudioDmaBuffers[39]`) gives LFTR (114). Takeaway: a `(i ^ 0) < N` LFTR steer can stand in for an SDK-style later loop on the same counter that was respelled as a pointer walk. 2. REFINES Q0582/Q0810 (uopt loop; related Q0693, Q0798; pins the 80150/55B20 `^ 0` lever): on an s32 counter, `(u32)i < 39`, `i < 39U` and an inline sizeof bound did not block LFTR (all 62, same as plain). uopt folds `| 0`, `+ 0`, `& 0xFFFFFFFF` and same-width casts on the counter, and LFTR goes ahead. It keeps `^ 0`, `<< 0` and `>> 0`, which emit no code and block LFTR (score 0).
