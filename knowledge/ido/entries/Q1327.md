Source: n64decomp/ido src/uopt/uoptreg2.c (IDO 7.1), confirmed against 5.3 traces. 1. uopt split() rule (explains Q1232; related Q1163, Q0998, Q1179, Q0492): when uopt splits a range during colouring, - the new piece starts at the first block that holds a store (or, failing that, a use) and still has a free register; that piece keeps the old candidate number. Trace "live range X: X split out Y" means X is the piece and Y the re-queued leftover; - the piece then adds successor blocks while `shared < regsleft && 2*regsleft >= numintf + shared` (regsleft includes the callee-saved registers; ranges already marked uncolourable don't count). It never grows from a block where the value dies, or past a call block in the main loop; - so where a constant range splits depends on how many interfering ranges it has seen, not on how the literal is spelled. The replay predicts all five traced builds and the permuter's zeros. 2. uopt compute_save (related Q1019, Q0492, Q1058, Q1084): savings = sum((loads+stores)*freq) minus movcost*freq per reload (needreglod) or save (needregsave) unit, divided by n. n = units + reaching blocks, compressed to 2 for n 2..5, 3 for 6..9, 4 for 10..13, and doubled for f64. Ties go to the lowest bit (strict >).
