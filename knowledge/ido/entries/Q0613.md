In minecartUpdateObstacleType3, `goto` from the case-0 then-arm to the case-1 body (the label sits at the head of the next case) changes register colouring even though control would reach the same code anyway. Without the goto, LR127 (`&gCurrentActor`) is coloured whole to one register: `sw s1,0x30(sp)`, then `lw s0,0(s1)` at each use. The goto adds a CFG edge, so the shared case-1 block has two predecessors (the then-arm and the jump table), and uopt splits that live range off $s1, which is what the target shows. The fallthrough form (score 4269) and an inverted early return (5224) both re-colour LR127. Evidence: .scratch/CleanMinecart25F0/uopt_obstacle3_goto.txt vs uopt_obstacle3_gotofall.txt. Keep such gotos as a Q0591 shared-tail goto.

**2026-11-17f correction (CleanminecartUpdateObstacleType3 0ce1bb40):** File src/minecart/25F0.c, minecartUpdateObstacleType3 u6bb91 FIXED (goto removed: case 0 falls into case 1 with `/* fallthrough */`, switch exits `break;` instead of `return;`; director: ordinary C). NEW (uopt regalloc/switch shape; related Q0559, Q0591, ido-uopt-coloring-rules guide): when a switch is a function's last statement, `break;` exits instead of `return;` add one live CFG node (the switch-end block survives only if at least one exit breaks), raising the saved-register first-use cost by 0.25 (nodes x 0.25, Q0559): &gCurrentActor saves 15; 59 nodes cost 14.75 -> $s1, 60 nodes 15.0 -> split. CORRECTS Q0613 (the goto adds no CFG edge: goto and fall-through graphs have the same shape; the goto adds one deleted node that still counts) and Q0954 (the after-switch block reproduced the split for the same node-count reason).
