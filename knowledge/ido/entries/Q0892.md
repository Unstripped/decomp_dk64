This adds one spelling to Q0816's table for member access on a typed pointer. In `csCmdBobbingLights` (src/global/478F0.c, b584f0), a two-point LERP macro reads fields of neighbouring entries. Written as `(&p[k])->f`, the field access is lowered and weighted like `p[k].f` (offset-first `addu`), not like `(p + k)->f` (base-first). The `(&p[k])->f` spelling left 18 diff lines, while `(p + k)->f` matched with 0. So taking the address of a subscript and then using `->` does not get the base-first order. It keeps the subscript's offset-first shape, which matches Q0813: every spelling of `&p[i]` puts the offset first. To get base first inside a member access, use `(p + k)->f` or `(&p[0] + k)->f` as Q0816 describes. Recorded during the 2026-11-15 cleanup of HackcsCondDepositItem.
