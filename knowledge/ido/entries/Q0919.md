In `vehicleUpdateMotion` (src/global/936B0.c), the HackvehicleUpdateMotion2 cleanup (ledger-only 7d9fd683, base dc093914, kept 54eada) found that a `u8` local array accessed only with constant indexes still stays in memory. The uopt listing shows its elements as variables that are not register candidates (`isvar M -25/-26` with no vreg). The target matches this with `sb`/`lbu` at `0x46/0x47(sp)`. When the same values were written as two `u8` scalars, both got registers and the score was 186. Q0494 only covered arrays with a variable-indexed access. This case shows that a local array of narrow elements can stay memory-resident with no variable index at all. So if the target keeps adjacent byte stack slots and you can't get them with scalars, try a small array. The same mechanism explains why the `fl[4]` steer array could not be replaced by two scalars plus padding: splitting it into scalars makes them register candidates and the stack slots disappear.
