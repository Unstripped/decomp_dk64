In a commutative s32 `+` where one operand is a bare deref `*p` of a local pointer, cfe emits the `*p` ilod first regardless of source order (`*h + y` and `y + *h` give the same ucode), so ugen's register naming follows. A struct field access `p->f` keeps source order. Typing the pointee as a struct turns an operand-order steer into ordinary C. (For array element vs named field order, see Q0604.)

Evidence: behaviourFlyPatrolWithCallback / actorAirPatrolStep (global/B7490.c): typing the void* Actor 0x178 component as `FlyPatrolComponent { s16 hoverHeight; }` and writing `y + patrol->hoverHeight` retired a comma steer (e1de6f, `lh t6,0(t2)` / `lh t8,6(v0)` at 0x1cd8/0x1ce0) and a `y - (0 - *h)` negation steer (831e55, `addu t2,t9,t1` at 0x22f4). Check with `as1probe.py ucode --cfe`.
