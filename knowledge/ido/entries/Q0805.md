A pointer walk over a global table hoists the table base into one s-register and then copies it (`move s1,s5`); indexing the table in every pass instead keeps `&table` its own address candidate (`lui/addiu s1`). When the target materialises the table address directly in the register the loop uses, write the loop with indexing.

Evidence: modelSlotSerializeAll (global/36880.c, merge 54a0243b). The same lever retired arcadeCheckStage3Collision's `(s32)` end cast (arcade/0.c, merge 8e1b647d, RELOC-EQUIV).
