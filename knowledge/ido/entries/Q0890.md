In `csCmdModelStepAnimation` (global/478F0.c, fixed in 9573b6), the target puts the global table address `lui v1,%hi(D_807481F4)` before the guard's branch at 0x7298. The function has a search loop guarded by an `if`. Writing it as `while (flag == 0)`, with the `flag = 0; i = 0;` inits inside the guarding `if`, makes uopt place that `lui` above the branch. This replaces an earlier fake `if (TABLE) {}` dead read in front of a do-while. The do-while forms scored 56. Moving the inits outside the `if` scored 41-44. So whether you use a pre-tested `while` or a do-while, and where the loop inits sit relative to the guard, decides if the invariant global address is hoisted above the guard. Try this before adding a dead-read hack, and see Q0130/Q0364 for related cases where the loop form changes hoisting.
