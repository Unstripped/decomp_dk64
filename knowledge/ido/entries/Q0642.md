In `eepromLoadPlayerData` (104F0), an untagged `KongInventory *base` copy existed only to own a frame slot (uopt_trace: without it only i's home moves sp+0x40 -> 0x44). An unused `s32 pad` declared ahead of `i` reproduces it, and the code reads the table directly (`entry = gPlayerInventoryTable[0].kong`). fdiff 0.
