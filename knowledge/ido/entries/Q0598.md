Spelling an element of a global array through an identity cast, `&((MapChunk *)gMapChunks)[i]`, matches where `&gMapChunks[i]` and `gMapChunks + i` do not: cfe builds the cast as a separate expression that is never CSEd against the plain `gMapChunks` load, so the base is re-loaded (`mapChunkReleaseAndAdvance`, `mapChunkEffectSetFlag`, `mapChunkFindNodeAtPoint`). Keep the cast as a view only where this is the evidence. CEAE0 (round 5) confirms that a same-type cast on an array element steers register allocation this way. F9450 (round 5): an identity cast `((T *)&g[i])->f` blocks cfe's CSE of a float load. Flipping the compare's operands gives the same codegen without the cast, so try an operand flip before keeping the cast.
