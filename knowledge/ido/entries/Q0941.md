`textDrawStringVtx` (src/global/100180.c, 1e50d1 fixed by replacing the file-local TEXT_GFX_CMD/QUAD/VTX macros with gbi macros, FAKE 3 -> 2; ledger 108db654, base e1a3636c). (a) cfe gives a local declared inside a nested block a slot after every gbi `_g` slot parsed before that block: the `ch != 0x20` block puts yoff..h at -69..-80 (fdiff 0). (b) Every `?:` and every post-decrement compare `i-- > 0` share one temp slot below all locals (-104 = sp+0x60); writing if/else instead of `?:` drops that word but moved s-registers (139+). (c) uopt operand order: with `a` a shared subexpression already in a register, `x = x + a - b - c` emits `addu t7,v0,t6` (a first) while `x += a - b - c` emits `addu t7,t6,v0` (0x162c). (d) `i-- > 0` becomes a single `blez` only when i copies a variable the decrement does not touch (`i = count /= 4`); `i = count / 4` gives slt + beqz (0x1560, 0x1728; cdb041 kept).

**2026-11-15c refinement of (d):** (unit "2026-11-15: cleanup HacktextDrawStringVtx3", a8c99e1f) the fused `blez` of `i = count /= 4; while (i-- > 0)` has two separate causes: (a) `i` copying ANY named variable fuses the compare, even an unrelated register-only local (`i = len = count / 4`); (b) the dead redefinition `count /= 4` adds a def+use of count in the flush blocks, which keeps count's priority high enough for s8. Without (b) count is homed at 0xa4(sp) (~320 lines) whatever copy is used, and site 2 reverts to slt+beqz (0x1764): the dead store is a priority lever on count, not a compare-shape lever. An untagged `s32 pad` first or last grows the frame 0xc8 -> 0xd0 (every word owned), as the Q0937 refinement predicts.
