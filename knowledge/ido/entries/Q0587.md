Case 0 of hudPauseMenuRender needed three things that one loop spelling gives: the entry guard reuses the count already loaded for `ph` (`lbu v0,%lo(D_807FCC4C)(v0)` … `blez v0`), the latch re-reads it through the table pointer reloaded from the stack (`lw t3,0x144(sp); lbu t5,0x2FC(t3)`), and `or s3,zero,zero` (`j = 0`) sits before the guard but after `addiu s6` (the hoisted `la gFrameCounter`). `if (D_807FCC4C > 0) { j = 0; fb = (f32)(u32)ph; do { … } while (++j < ((u8 *)tab)[0x2FC]); }` put `move s3,zero` after the branch; `j = 0;` before the `if` scheduled it two slots early (as1 orders ready instructions by source line, the init's own line beating the hoist's loop line). `for (j = 0; j < ((u8 *)tab)[0x2FC]; j++) { … fb = (f32)(u32)ph; … }` with `ph = ((u8 *)tab)[0x2FC] * 0x34 - 0x34` does all three: uopt CSEs the guard's load with `ph`'s (same expression, constant-propagated `tab`), the latch copy after the calls reloads `tab`, the invariant `fb` conversion is hoisted after the guard, and the init shares the loop's line so the critical-path tie-break favours `addiu s6`. `D_807FCC4C` and `gPlayerInventoryTable+0x2FC` assemble to the same bytes (`objdiff` reports only the relocation symbol); spelling the guard with the symbol and the latch with `tab` cannot be CSE'd in our build because splat gives them different symbols.
