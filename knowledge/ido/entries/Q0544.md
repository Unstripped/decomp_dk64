as1 gives a switch's non-return `jr` the live-ins of every jump-table target of the procedure, so a register those targets do not read counts as dead on the path to the switch and as1 hoists across it (Q0412's default-arm hoist). The natural FAKE-free C of `func_806F03C4` and `scriptOpPlaySoundAndShake` matches exactly (full 0) once that jump is treated as live (`as1probe try --insert <j>:live`, `live=0x40` resp. `0x06220000`, or an as1 patched to make a `jr` without `.livereg` all-live while keeping its successors); the same patch changes 129 matched functions, so the original's jump liveness was precise elsewhere and no C producer is known. Details: guide ido-backend-record-pipeline, section 'Switch jr liveness'.

Revisit 11 (2026-11-06) closed one more route: uopt's `base_in_reg` sets `unaltab`/`spunaltab`/`gpunaltab` (the `.alias`/`.noalias` records Q0461 needs before a label) only when the base address is `islda`/`isilda` (`&local`, `&static`, `&arr[i]`), never for a loaded pointer, so `func_806F03C4`, which works only through loaded pointers (`gPlayerSlots`, `D_807FBB48`, `gActivePlayerState`), cannot get one from C without adding an address-of the target lacks.

Revisit 12 (2026-11-06): `scriptOpPlaySoundAndShake` matched without any jump liveness: its hoists sat inside as1's XBB source window and six dead `if (arg0 && arg0 && arg0) {}` guards pushed them out (Q0548). Live-jr probes block the same hoists by liveness but were not the mechanism there; try Q0548 first on any hoist this entry describes.
