In func_80610268 (14CF0) the received message lives in a variable whose address is passed to osRecvMesg; the target has bne s1,t8 and really stores the masked id back to sp+0x34 (behaviour, not a steer). Comparing the address-taken receivedMsg directly with the masked value stored back into it, written `while ((s32)receivedMsg != targetTaskId);` with receivedMsg typed `OSMesg` or `void *`, is fdiff 0; no receivedTaskId copy local is needed.

Corrected 2026-11-14 (PolishGlobal14CF0): this entry previously said only copying the value into a plain local first restores the bne s1,t8 order; the direct compare above matches too.
