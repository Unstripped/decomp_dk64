Extends Q0669: byte strings stay `u8 *`, but a parameter that only forwards its string to another call (`_strchr`, `_strcpy`) and receives both `u8` buffers and string literals is declared `void *`: `_strtok` delim, `_strspn` set (boot/3630) and `gfxResourceSetString` str (1025E0). That clears every literal-vs-`u8 *` W709 at their callers (cfe 89 -> 84) with no new casts and no codegen change. A function that reads `*str++` itself (`textDrawString`) keeps `u8 *`.
