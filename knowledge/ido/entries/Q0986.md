This came up during the 2026-11-15 cleanup of `HackmapChunksInitFromMapData` (unit 4a8a7f/5f674b, fixed). The cleanup split one register-allocated local that was reused for several jobs into separate role-named locals. The only change in codegen was the frame size, because cfe gives every declared local its own stack slot, even when the value never leaves a register (see Q0386). Shrinking the adjacent m2c-sized byte buffer by the same number of bytes (`u8 buf[0xE38]` -> `u8 buf[0xE30]`) brought the frame back to the original size and kept every other slot at its original offset. The lead accepted this: the buffer's size is m2c's guess to fill the frame, not evidence from the original source, so it can be adjusted to absorb readability splits. This only works when the change is limited to the frame size and the buffer sits next to the new slots in the layout.
