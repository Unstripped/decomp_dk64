In critterBattleArenaUpdate (critter/5110), a dead `if (rewardFlag && rewardFlag) {}` (FAKE 68dc48) was kept to promote rewardFlag to a register. The real cause: the sibling anti-tamper path called `flagSet((gCurrentMap == 0xB6) ? 0x184 : 0x183, 0, 0)` with the flag id inline. Writing it as `rewardFlag = (gCurrentMap == 0xB6) ? 0x184 : 0x183; flagSet(rewardFlag, 0, 0);`, the same flag-id role as the reward path's `flagSet(rewardFlag, 1, 0)`, raises rewardFlag's use count the same way with no dead code (fdiff 0). Before keeping a dead self-test that only raises a local's priority, look for a sibling path whose call argument could live in that local with the same role.
