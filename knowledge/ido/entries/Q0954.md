In minecartUpdateObstacleType3 (src/minecart/25F0.c, u6bb91), the matching code keeps the goto from the case-0 then-arm into the case-1 body (Q0613). The shared tail at 0x2300-0x2320 was re-verified. I tried a goto-free version: move the shared case body to a block after the switch, make case 1 `break;`, and have the then-arm break into that block. This reproduces the extra CFG edge and the t0/s0 split of `&gCurrentActor`, with the reload in the then-arm's `b` delay slot. However, it puts the case-2/default bodies ahead of the case-1 body and renumbers the temps (88/87). The after-switch block splits the address web the same way the goto does, but it changes the order of the case bodies, so it does not replace the goto. Keep the goto, or use one of the Q0591 patterns that preserve body order. This was a ledger-only record: a04efaed, base 5c8c62b7, unit "2026-11-15: cleanup HackminecartUpdateObstacleType32".
