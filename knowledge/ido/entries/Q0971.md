Seen in the HacktagBarrelOrbitKongs2 cleanup unit (2026-11-15). This extends the Q0554 FIFO model. When no other value is holding any of them, ugen's integer scratch free list works as a strict 10-register round robin from the start of the function, in the order `$14 $15 $24 $25 $8 $9 $10 $11 $12 $13`. Each allocation advances the ring, including allocations for code that as1 deletes later as dead or redundant. That deleted code is gone from the final listing, but it still decides which register a later loop gets, through the number of allocations mod 10. In the target, the loop's `mfc1` lands in `t7` ($15), which requires 30 allocations before the loop. Without the extra expression chain, the count is only 15 and the loop gets `mfc1 t2` ($10) instead (full=33). To fix this kind of mismatch, count the scratch allocations before the loop mod 10, including those as1 throws away. Then add or remove C expression work before the loop until the count lines up, rather than editing the loop itself. This only applies while nothing else is holding scratch registers. Once values stay live, the FIFO order from Q0554 takes over.
