This is the same unit as Q0744 (cleanup HacktagBarrelOrbitKongs2, `tagBarrelOrbitKongs` in global/80150.c), at function 8074ea, which is now fixed. When a `void *` parameter is copied into a typed local and the loop walks through that local, the strength-reduced walk gets different registers than in the target. Changing the parameter's own type to `TagBarrelData *` and indexing `arg->kongs[i]` in a `for` loop gives the target's walk: `move s3,s4` / `lw s2,8(s3)` / `addiu s3,s3,4`. Removing the typed-copy local shifts the stack frame, so an extra untagged `s32 pad` local is needed to keep `centerX` at `0x70(sp)`. So a typed copy of an untyped parameter is not a neutral way to add a cast. It adds one more candidate for register allocation, which changes the priority balance between the walk and the data parameter described in Q0744. Try typing the parameter directly before adding a cursor local or a copy.
