`lightSampleColorAtPosition` (leftovers revisit 13) matched with no FAKEs once its delta/normal scalars became local arrays (`f32 d[3]; f32 n[3];`), after 19 attempts with scalars, node pads and dead guards. (1) Array elements are not vreg, so `clkilled()` treats them as killed by every call: liveness and reaching stop at the call, the pre-call piece is stored (`rstr`) before the `jal`, and the post-call piece starts with a reload (`rlod`) at the first block that references the element (here the join after `if (dist == 0.0f) dist = 0.1f;`); as1 then hoists the first-needed reloads into the return block and fills the delay slot. A scalar's reload always stays in the return block (Q0561 (4)). Loads of non-vreg locals are never forwarded, which also explains kept stores with no reload (nx/ny) and immediate store-then-reload (nz). (2) `indirectaccessed()` marks a block whenever a load's base is a pointer variable or computed address (`aliaswithptr` is always true for C), which makes local arrays uncolourable there; `findbaseaddr()` strips `ixa`/add down to a global's `lda`, so `D_807F7BC8[i].f` keeps them colourable while `p = &D[i]; p->f` does not (full 192). uopt still builds the target's pointer loop (`s0 += 0x40`), so a pointer loop in the target does not imply a pointer local in the source. (3) cfe reorders commutative operands that are array-element loads (scalars keep written order): the natural `d[0]*d[0] + d[1]*d[1] + d[2]*d[2]` gives the target's `d2² (d0² d1² add) add`. (4) Hint: a park imitating x,y,z homes with reversed scalar declarations (`f32 dz; f32 dy; f32 dx;`) is a sign the source used an array.
