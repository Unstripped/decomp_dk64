A pointer variable copied into a second variable (`obj = p;`) is merged back into one web by uopt copy propagation, so `lw s1,36(a0)` loads straight into the callee-saved register and every use of `p` becomes `s1`. The target pattern `lw v0,36(a0); sw t8,8(v0); move s1,v0; lw t3,0(v0)` (early uses through a temporary-register web, later uses through the saved-register web, plus a `move` between them) appears when `p` is REASSIGNED after its last early use and before the first use of `obj`: copy propagation of `obj = p` is only valid up to the redefinition, so later uses keep `obj` and the two webs stay separate. The reassignment is a dead store (`p = (ModelSlotObjHeader *)seg;`, `p = 0` and `p = arg0` behave the same) because copy propagation runs before redundant-store removal.

Use `p` (not `obj`) for the early uses (`p->unk8 = ...; if (!(p->unk0 & 0x10) ...)`) and `obj` for the later ones. A second explicit load (`obj = arg0->unk24` after the store through `p`) instead gives a real reload, and CSE through `arg0->unk24` is killed by the store.

Result on `modelSlotResolveAssetTextures`: the first 17 target lines became exact, full 33 -> 29 (text 29, shape 4), but 114 instructions vs the target's 113 (deadsweep's 122 vs 121 are normalized rows including relocations), so it stays a draft. Remaining there: flags in `a3` (uopt picks the cheapest legal register, ties lowest id: `a3` needs v0..a2 forbidden or a call-argument hint; `graphhead->regsused` forbids the precolored parameter registers only for ranges live in the entry block) and the diff/A8/A0 webs (one `pad` variable gives them one register; the target has v0/v1/a0 as separate webs).
