478F0 csCmdHubWorldItemsAdjust: `idx = frame + add` and `idx = add + frame` both give `addu a2,v0,t1`; only `idx = frame; idx += add;` gives the target's `addu a2,t1,v0` at 0x6798 (kept FAKE bf5dac, a copy reused for the sum).

Correction (2026-11-25c, CleancsCmdHubWorldItemsAdjust, 1a99d6a4): uopt does not canonicalise the add: cfe loads the operand that needs converting first. With equal widths source order holds (`s32 add`: `frame + add` gives `addu a2,t1,v0` 0x6798), so the split `x = a; x += b;` is only needed when one operand is narrower (Q1682).
