A `u32` expression passed to a pointer/`s32` parameter puts the `ucvt` in the argument slot and the shared sub-expression lands in `s4`; with `u32` parameters it is `a0` plus a spill. The callees' parameter types are part of the lever (`heapMoveWords`/`heapRebaseHandles` now take `u32`). The same conversion explains "callee prototype steer" declarations: an `s32` sound handle passed to `n_alSndpStop(struct GfSndState *)` changes register preferencing (a0 vs a3 in `sfxPlayAtPositionForPlayer`), so files kept `void n_alSndpStop(s32);`. Typing the handle variables and the `PlayerState` field as `struct GfSndState *` removes the conversion and lets the shared prototype apply unchanged (all `n_alSndpStop`/`n_alSndpPostEvent` steers in 7130, arcade/0, bonus/12A0, global/19A00 and jetpac/0). Fix the argument's type, not the callee's prototype.
