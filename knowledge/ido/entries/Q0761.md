A function-local `static` (not only a `static volatile`, Q0564) stays a native S variable in uopt (`isvar S`, ustr/uadd of lod, no lda candidate), so every access keeps its own `lui`/`%lo` pair. The same variable as an extern global or file-scope static becomes one lda address web that can be coloured into a callee-saved register.

Evidence: mainThreadHalt (global/0.c), a `static u64` stored once and read in a while-loop test: target keeps separate pairs at 0x360-0x36c, 0x370-0x380 and 0x3bc-0x3cc. As a global or file-scope static it became lda web candidate 25 coloured into $s0 (lui/addiu s0, sw s0 0x18(sp), frame 0x50 vs 0x48). This retired a `*(q = p)` pointer-copy FAKE.

Placement (2026-11-15, HackactorNodeRingUpdate2, src/global/C1E70.c actorNodeRingUpdate 4bfffc; HackgfxBuildScrollingBackground2, 109660): IDO lays out the TU's .data in source order of definitions, function-local statics included, each 4-aligned: `sRingSequence`/`sRingSequencePos` land between file-scope `D_807506A4` and `D_807506B8` because `D_807506B8` is defined after the function. Statics initialised with `= 0` also go to .data, not .bss. (109660's statics landed after all file-scope .data only because they came last in source order.)
