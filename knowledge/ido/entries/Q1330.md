File src/global/6AD90.c: collisionCheckTriangleWindingS16/F32 and collisionCheckBoxTriangleWinding. The 27898a site is kept in all three (3 diagnose nohit, 3 reviews). The director agreed not to adopt the `cross[2]`-index spelling: it matches, but picking the index only for its stack slot is a steer. 1. EXTENDS Q0561 (uopt/ugen frame size and stack slots; see Q0467, Q0361): the frame reaches down only to the lowest element the code actually uses, not to the bottom of the declared array, so unused elements below can sit below sp. Evidence (S16, base d25a9bbe), declared `f32 v1[3], v0[3], cross[3]`: - using only cross[1] keeps the frame at 0x20 (not 0x28) and stores to 0(sp); - cross[2] stores to 4(sp) and matches; - cross[0] grows the frame to 0x28. General form: element k of `f32 a[N]` declared right after v0 lands at sp + 0x8 - 4N + 4k, and a used element at a negative offset grows the frame by 8. So the word directly below the previous array can only be the last element of the array declared next, which is why no three-element Y-component spelling can match these functions.
