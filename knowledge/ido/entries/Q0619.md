In `raceManagerBehaviorUpdate` (7BD0), the target stores the same value to `ActorSub4` 0x34/0x38/0x3C (scaleX/Y/Z) through a strength-reduced loop: `addiu v0,v0,4` with `swc1 0x34(sub4+v0)`. Three named stores (`sub4->scaleX = s; sub4->scaleY = s; sub4->scaleZ = s;`) cannot produce that loop. The match needs `for (axis = 0; axis < 3; axis++) sub4->scale[axis] = s;`, so `include/actor.h` gained `union { struct { f32 scaleX, scaleY, scaleZ; }; f32 scale[3]; }` at the same offsets (cleanup round 16; only 5 functions lost fresh rungs to the header change). When asm walks consecutive fields with a +4 induction register, look for an array spelling of those fields.
