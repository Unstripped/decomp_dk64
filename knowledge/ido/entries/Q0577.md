In `effectSpritePoolFadeOut` (`src/global/114270.c`), the function returns `s32` and handles three logical conditions:
1. `*queue != 0`: updates alpha, registers render callback, and does `return 0;`.
2. `*queue == 0 && D_807FDA1C != 6`: frees resources, sets `D_807FDA1C = 6`, `D_807FDA28 = 0`, and does `return 1;`.
3. `*queue == 0 && D_807FDA1C == 6`: in target assembly, control falls through the branch `beq t0, at, 2f00` directly to function epilogue `lw ra, 44(sp) ... jr ra`. At this point `$v0` was never written since its initial load of `queue = D_807550E0` at the function entry (`lw v0, %lo(D_807550E0)(v0)` at 0x2d4c), leaving the non-zero pointer value in `$v0`.

The caller at `src/global/8F4B0.c:501` checks `if (effectSpritePoolFadeOut() != 0) { csState->unk0 = 0; }`. On the third path, the non-zero pointer value in `$v0` causes the condition to evaluate as true.

Attempting any explicit return (`return 1;`, `return 0;`, `return (s32)queue;`, or single exit variable `ret`) alters IDO's register allocation and emits a jump / move instruction before the epilogue that does not exist in the target. The fall-through return is unresolved and tagged with `// FAKE` per AGENTS.md conventions.
