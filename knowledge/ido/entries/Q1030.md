A dead `!g && !g && !g` test on a global pointer works by the number of reads, not by blocks: each read adds savings to the global's load candidate and stretches a competing reload, so the term count must match exactly. Guards on other locals with the same shape do not reproduce it.

Evidence: playerTurnByStickX (global/E4090.c): 1/2/3/4 terms give 16/16/0/2 (`||` the same); each read raises the gCurrentActor load candidate {645} (1.5 -> 1.71) and stretches the yaw reload {103} (2.0 -> 1.5); `!delta` x3 gives 14, `!yaw` x3 25.
