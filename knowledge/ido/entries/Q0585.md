A short-lived pointer that the target keeps in memory although every `$s` register is free in its range (hudPauseMenuRender's `list = heapAlloc(0x1F40); heapFreeDeferred(list); gSPDisplayList(dl++, list); dl = hudSetupTextState(list);` → target `sw v0,0x13C(sp)` then one `lw a0,0x13C(sp)` feeding both the store and the call argument) is an **uncoloured candidate**, not a plain memory variable: an array element or `*&list` gives a tracked load into a ring register and a second `lw` for the argument. uopt colours it (`adjsave 1.5`, `$s0`) unless its live range is stretched until the savings per block drop to 0; then it is split and only the prologue piece gets a register, which is `$a0` because the next use is the call argument — exactly the target's `lw a0`. A dead `if (list == NULL) {}` is the lever (uopt keeps the comparison operand as a use, as1 deletes the dead `sne`); the permuter found the same (`if ((list && list) && list) {}`). **Placement matters**: before the `switch` it changes nothing else; inside case 1, case 2 or at the function end the stretched range moved the reload of another split piece (`hud` → `$a0` in case 1 moved from after `jal hudDrawItemLabel` to the loop head, losing `lwc1 $f12,4(a0)`), although `uopt_trace` showed identical colours — the piece's load placement, not its colour, changed.
