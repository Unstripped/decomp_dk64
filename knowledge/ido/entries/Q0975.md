In `hudPauseMenuAddCounter` (global/ACDC0.c), the untagged `pad`/`pad2` locals were not filler. They were the stack home slots of the CSE'd float temps `640 - x*4` and `480 - y*4`. Replacing the pads with real named locals declared as `f32 fx; s32 idx; f32 fy;` matches only in that declaration order. The other versions tried all fail: keeping the pads, `idx`-`fx`-`fy`, and `fx`-`fy`-`idx`. Declaration order sets the slot assignment, so the `s32` index has to sit between the two float temps. When a matching function has pads next to reused float expressions, try promoting those expressions to named locals and permuting their declaration order before you settle for anonymous pads.
