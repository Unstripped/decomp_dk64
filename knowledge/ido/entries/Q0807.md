IDO emits no narrowing for an argument to an unprototyped (K&R) callee, and a `(u8)` cast on a value that is already u8 emits nothing. So an `andi aN,sX,0xff` at a K&R call on an already narrowed value is a mask written in the source (`(u8)i & 0xFF`, or `& 0xFF` on a u8): an `// ORIG:` site, not a steer. A `(u8)` cast of an int loop index is one shared value reused for later u8 conversions; only an explicit `& 0xFF` on top adds the second `andi`. Caution: under a u8 prototype the plain argument converts in place, so first check whether the extra narrowing copy comes from a redundant caller `& 0xFF` (slotQueueInit in global/FCCD0.c: ORIG claims da5663/06d21a refuted this way).

Evidence: eepromLoadPlayerData (global/104F0.c): c3c889 -> ORIG (entry `andi s5,a0,0xff` at 0x2470, `andi a0,s5,0xff` at 0x24e0); eepromValidateSaveSlots: `andi sX,i` + `andi a0,sX` = `(u8)i & 0xFF` (b73cc4, b73cc4#2 -> ORIG at 0x14ec, 0x14f4, 0x156c, 0x1630); all lead-verified.
