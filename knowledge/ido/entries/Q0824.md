IDO omits the narrowing of a call result only when the callee's declared return type is u8 (it trusts the zero-extension); with any wider declared return (s32, u32, u16) storing the result to a u8 local adds `andi vN,v0,0xff`. So a caller that uses v0 unmasked as a byte was compiled against a u8 return, and a caller that narrows the result itself right after the jal was compiled against a wider return. When both caller groups exist, one shared prototype cannot satisfy them: the narrowing caller's local wider declaration is genuine call-site evidence (`// ORIG:`, Q0486 class).

Evidence: func_806BE09C (global/C2A90.c): `jal mapGetHubWorldIndex; sll v1,v0,1; sb v0,73(sp)` (u16 local gives sh, s32 sw); jetpacUpdateStateAndInput (jetpac/0.c, 0x11d4) narrows after the call vs spawnFlagConditionMet (global/135D30.c, 0x80c).
