In `actorBoneChainSwingUpdate` (global/9CE20.c, 04e08b fixed, 5f92e4 -> b0cf60, FAKE 2 -> 1; ledger 6010d93c, base 602f275c) two dead tests were removed. (a) An early `continue` in the loop body replaces a dead test of the loop bound before the loop (`if (n == 0) {}`). Both lower the adjsave of the converted (ucvt) bound by the same amount (7.33 vs 7.67, against 11.0 with neither), so `i` gets coloured first. (b) In a loop body of the form `if (x == 0) store;`, writing `switch (x) { case 0: store; break; default: break; }` adds the same uopt blocks that a dead test before the loop or a dead `if (data) {}` before the store would add. The explicit empty `default` is required: without it the score is 261, and if/else forms give 149. The lead ruled that a one-case switch with a load-bearing empty default counts as a codegen spelling, so it stays tagged (b0cf60). The permuter ran 900 s from base 7361 and reached best 0 only by swapping steers. Merge 6ea097ac.

**2026-11-15c refinement:** (actorBoneChainSwingUpdate, unit "2026-11-15: cleanup HackactorBoneChainSwingUpdate3", 1052ffb7) the one-case switch with an empty default works through two independent CFG properties: (a) the loop head's non-store edge passes through a block, which adds a block to the loop-bound ucvt range (11.0 -> 7.33, i.e. 22/2 -> 22/3: adjsave is savings / blocks); (b) an empty block between the head test and the store block makes uopt drop the loop's store-constant candidate (`li t4,80` rematerialised in the loop instead of coloured and hoisted). An early `continue` gives only (a); a default-less switch gives only (b). For the dead-guard position rule and the unrelated-local test, see Q0908's 2026-11-15c classifier.
