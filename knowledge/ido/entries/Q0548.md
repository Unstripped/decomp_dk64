as1 `schedule` (XBB) scans, for each stalled destination block, the blocks after it that it dominates, sorted by (weight, block number) with weight 1 + 3 x control depth, and stops after about 11 candidates (limit 10 at `0x42ace4`; 100 when the loop record word 4 is non-zero). A hoisted `lh`/`li` from a later block therefore disappears once enough same-weight dominated blocks precede it. C can add such blocks: each dead `if (X && X && X) {}` with a register-held X (an unmodified pointer argument) survives uopt as one `fjp` to the next label, ugen emits `beq X,0,Lnext; Lnext:`, as1 counts it as a source and later turns it into a NOP and deletes it, so no instruction remains. Only the triple form works: `X && X`, `X || X` and plain `if (X) {}` leave no block, and terms needing loads leave real code. Place the guards in the straight-line region of the destination's weight after the destination and before the hoist sources; count = 11 - the source's current rank. In `scriptOpPlaySoundAndShake` six guards between the switch join and `mapActionLookupEntry` (plus a `volatile u8` local, whose loads are never hoisted) removed the then-arm's `lh t2,78(sp)`/`li a1,10`/`li a2,8` hoists into the unk2C0 test block: matched (revisit 12). This supersedes Q0544's switch-jr-liveness reading for that function: live-jr and dead-read probes block the same hoists by liveness but are not the mechanism.
