In `mapChunksInitFromMapData` (global/55B20.c, function 512c53, unit "2026-11-15: cleanup HackmapChunksInitFromMapData", merge 417ec166, record a63d5c8a), uopt gave the spilled loop temporaries stack slots in reverse order of their first appearance. Writing `size = n * 12` as its own statement makes the multiply appear first. Using a typed index `T[n]` makes the base address appear first, which swaps the two slots. The uopt trace shows the matching version using 216/218/220, while the typed-index version uses 216/218/219. To control the slot order, choose which temporary the source computes first. Splitting the scaled offset into a named statement is one evidence-backed way to put the multiply first. This extends Q0534, where named-local versus repeated-expression choices decide homes in this same function, and Q0563, which covers how spilltemps are placed in the frame. The result was observed only in this loop. It was not tested elsewhere.
