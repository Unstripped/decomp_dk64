mapPolyClipToFrustumPlane used `cur = in;` (a redundant alias) so that `cur` numbered before `planeIdx` on an exact s-register tie (Q1551). uopt -l 6: base cur bit 0 -> s7, planeIdx bit 18 -> s8; alias dropped with `plane = &gFrustumPlanes[planeIdx]` kept: planeIdx bit 15 -> s7, cur bit 25 -> s8 (6 lines). The `plane` pointer local, set before the loop, gave planeIdx its first reference ahead of the loop variables. Dropping it and spelling both distances through render.h `PLANE_DIST(gFrustumPlanes[planeIdx], ...)` moves planeIdx's first reference into the loop after `cur = &in[i]`: cur numbers first again (`move s7,s2` 0x7584, `lw s8,152(sp)` 0x7534), uopt still hoists the plane address into s4 (`addu s4,t8,t9` 0x754c), frame unchanged, full=0 (LeverScout27, merged c4161892). Resolves Q0575's alias explanation without the alias.
