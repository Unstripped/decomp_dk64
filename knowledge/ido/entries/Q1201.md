In boot/3D20 vsprintf the e-arm zero pad keeps three tagged steers (69d5aa `d = width`, e415e5 `if (padChar == 0) {}`, 7dcd26 `if (d) {}`) that give `d` a v0 range. Without them, `for (d = elen; d++ < width;) { count++; *buf++ = padChar; }` reproduces every register of the function (full=5: elen/fneg2 a1, s3/s4, the v0 CSE at 0xabc-0xb4c): the counter itself supplies that v0 range. Only 0xb9c-0xbac differ: the target counts down on `width` in t0 with the test in v1, the up-counter steps `d` in v0. Neighbours: `d < width--` copy-propagates d into elen (154), `++d <= width` 355 and `d < width; d++` 323 change the branch layout, `while (d++ < width)` 6. Permuter from the 5 body: base 45, best 45, 900 s. Extends Q1193 (a two-counter countdown keeps both counters).
