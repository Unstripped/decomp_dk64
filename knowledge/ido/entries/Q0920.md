In `HackvehicleUpdateMotion2` (function ebb5e5, kept; unit 2026-11-15 cleanup), the FP register of a CSE'd field read depends on interference inside one block. The `waterY` field read became uopt candidate 24, and it stays live into the buoyancy then-block, where `tmpB` is defined in `$f0`. Because the two clash there, `waterY` was coloured `$f2`. Caching `waterY` in a local before the compare removes the clash, and it then takes `$f0`. This fixed the diffs at 0x136c-0x14e8 (-l5 adjsave dump). This is the per-block interference rule of Q0523 applied to an FP CSE temp. Like Q0589, the fix is about how the read is written in source (a cached local vs a re-read field), not about adding dead guards. When a CSE'd float read lands one register above the target, check which block it shares with a temp that already owns `$f0`.
