Two guards (`if (i && sideC) {}`, `if (sideC && sideC) {}`) only made sideC appear before sideP in the candidate table (Q0297). One `sideC = 0;` right after `i = 0;` does the same; placed before `i = 0` it steals i's register. Net 2 guards -> 1 tagged init per function (collisionCheck(Box)TriangleContainsPointXZ). A dead store may not leave a later read uninitialised: deleting an initialising store whose only reader is a dead test is rejected.
