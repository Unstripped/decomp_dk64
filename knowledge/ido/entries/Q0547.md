Observed on `modelSlotResolveAssetTextures` (compared by deadsweep's normalized disassembly rows: instructions plus relocation rows; the target is 113 instructions, 121 rows). Fact 1: in the tested variants, a body that calls f(A0, A0 + len*8, ...) coloured the first call's pointer `a0` when the pointer was its own variable defined BEFORE the length was derived from it: `pad = seg->unkA0; sp24 = ((u32)(seg->unkA8 - pad) >> 3) * 8;` dropped the extra `move a0,v1` (121 rows of 121, full40 shape2). Reusing one holder for the length first (`pad = A8 - A0; ...; pad = A0`) coloured it v1 and the holder a0, costing the move (full29 shape4, 122 rows vs 121). Other holder orderings were tried (162 pad/pointer forms, 8 diff-variable forms); none beat these two, so the pointer-first form is not shown to be the only way. Fact 2: joining the arm's first 12 statements on ONE source line (per-line comments stripped, one trailing FAKE/LAYOUT tag) took shape 4 -> 1 at unchanged full 29 (as1 `.loc` scheduling barriers). The permuter's best output (score 630 -> 415) was this join, so try line joins on a near-miss whose shape row, not its register row, differs. Fact 3 (observed in the `-l 5` trace of the tested variants, reg ids 1=v0 2=v1 3=a0 4=a1 5=a2 6=a3, 14=s0): node 0 `regsused` is {a0,a1,a2}, the entry-passed registers of the 3-parameter K&R function, and call-bearing nodes list v0/v1 and a0-a3 in `regsused`. HYPOTHESIS, not verified: the target colours `flags` a3, which needs ids 1-5 forbidden when `flags` is coloured; one reading is that `flags` shares an early node with the entry pieces of arg0/arg1/arg2, `p` (v0) and a v1 web, and that the `&arg2` and `arg0->unk20 && arg0->unk20` FAKEs instead put `flags` in node 5 (it then forbids only {v0, s0} and takes v1). Removing the dead test did not give a3: it shifted the ugen temp ring (full47). Not solved: flags a3, A8/diff v0/v1 order, ring t1/t2.
