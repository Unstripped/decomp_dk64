In a body that calls f(A0, A0 + len*8, ...) the first call's pointer web gets a0 (call-argument legal set) only if the pointer is its own variable defined BEFORE the length is derived from it: `pad = seg->unkA0; sp24 = ((u32)(seg->unkA8 - pad) >> 3) * 8;` colours the pointer a0 and drops the extra `move a0,v1` (count-exact 121/121, full40 shape2 on modelSlotResolveAssetTextures), whereas reusing the same holder for the length first (`pad = A8 - A0; ...; pad = A0`) colours it v1/a0 in the wrong order and costs the move (full29 shape4, 122 vs 121). Independently, joining the arm's first 12 statements on ONE source line (strip the per-line comments, keep one trailing FAKE/LAYOUT tag) took shape 4 -> 1 at unchanged full (as1 .loc barriers): the permuter found it as its best hint (score 630 -> 415 -> 290), so always try line joins on a near-miss whose shape row, not its register row, differs. uopt -l5 facts used (reg ids: 1=v0 2=v1 3=a0 4=a1 5=a2 6=a3, 14=s0): a candidate live in a block that holds a call also forbids the return/argument ids of that block; node 0 regsused is the entry-passed a0-a2 of a 3-parameter K&R function, which is why a web living in the first real node can only reach a3 (the target's flags colour); the head FAKEs (`&arg2`, `arg0->unk20 && arg0->unk20`) split that head into nodes 1-4, so flags colours v1 instead. Not solved: flags a3, A8/diff v0/v1 order, ring t1/t2.
