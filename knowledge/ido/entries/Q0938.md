In `dlAppendTextureLoad` (global/1135F0.c, at 9fb5c4), the match relied on a dead `if (width && width) {}`. Running `uopt -l5` without that test shows width's adjsave at 23/12 = 1.92, which loses to the `gCurrentTexture` address at 25/12 = 2.08. The switch selector temp also starts in the entry block, whether it is a `u8 type` local or the bare field. It then interferes with texture `a1` and glistp `a0` and takes `t1` away from the 0x400 constant. Two fix the match (fdiff 0): two extra width/height uses in block 0, written as `lrs = width; lrt = height` copies passed as gDPLoadTextureTile's lower-right corner (they reuse the old `s32 pad[2]` words), together with switching on the field directly. Lead ruling: a copy local that replaces a dead test is a copy-temp steer (ladder rung), so it stays tagged FAKE and the count is unchanged at 2, but the dead test is gone. Counter-example: a literal 0 for uls/ult folds in cfe and spills the LoadSync/LoadTile temps (547), as in Q0764. Merge eeb357de, ledger 9ab7456b, base c4d94b20, tag 29d528.
