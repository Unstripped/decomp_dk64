Seen in `csCmdModelStepAnimation` (src/global/478F0.c, around 0x72e8), unit "2026-11-15: cleanup HackcsCondDepositItem". If the loop is written with an index (`arr[i]`), uopt strength-reduces it to a pointer. ugen marks that pointer `.noalias $3,$sp`, so as1 can move its spill store into the delay slot of the `jal`. If the loop walks a user-declared `s16 *p`, ugen emits no `.noalias`, and the spill store stays before the `jal`. So when the target has the spill in the delay slot, the original was an index loop. When the spill comes before the call, it was a hand-written pointer walk. A related point on the frame: unused scalar locals still get stack homes in declaration order. Adding or removing an unused `s32 i` moved the spill slot. This works like the slot effects in Q0644, so unused declarations can be used to place the spill slot.
