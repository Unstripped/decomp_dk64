Same unit/function (mul.s operand order; extends Q0966): the operand order is fixed in the ucode before regalloc. When the float product is the whole value stored into an integer local (`ang = fa * flyY`, `(s32)(...)`, `(s16)(...)`, either source order), the uopt candidate table shows `umpy{load}{fa}` -> `mul.s $f18,$f16,$f0` (0x1328); inside a cast chain feeding an addition (`(u16)(s32)(fa*flyY)`) it stays `umpy{fa}{load}` (fa first). See also Q0584.
