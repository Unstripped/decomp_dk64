Extends Q1445/Q0559 (related Q0908): a dead test that only adds a basic block changes the callee-saved register order, and where the block goes matters. Any guard that is a pure block split works there: `if (1) {}` reproduces it, while `if (0) {}` is folded away and scores the same as removal. It works only after the last call of either arm, not at the function top, at an arm's start, or around the node and res tests. Rewriting the arm without a guard does not add the block.

Evidence: global/36880.c modelSlotResolveAssetTextures, site bb36c3, kept (unit CleanmodelSlotResolveAssetTexturesb, merge 361a0c36):
- fdiff 0: `if (1) {}`, `if (res) {}`, `if (obj) {}`, `if (force) {}`, `if (textures) {}` after the fourth call, and `if (1) {}` after the else-arm `modelSlotClearAssetTextures` call.
- Elsewhere: function top 71; kind-1 arm start, before the node test or after the res test 103; `if (node) {}` and `if (0) {}` 64 (= removal).
- Else-arm respellings without a guard (swapped arms 65, nested `else { if }` 64, return after the clear call 64) do not add the block.
- Register order: with the block obj is s1 and seg s0. Without it obj takes s2, seg s1, and textures shares s0 with node, which grows the frame to 0x50.
- Permuter, 900 s: all 11 zeros put an empty guard back in a new block.
