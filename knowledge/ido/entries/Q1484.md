Supersedes Q0810's general claim that an inline `sizeof(t) / sizeof(t[0])` loop bound blocks uopt's end-pointer rewrite (LFTR) like a `U` literal. When the loop counter only indexes that same table, the sizeof bound still allows LFTR and full unrolling:

- gridCollectActorsInRange keeps LFTR: `addiu s3,s3,20; bnel s3,t7` at 0x324c-0x3250, end `gGridTypeTable+0x348`.
- actorTypeIsRespawnPickup (a constant-trip scan with an early return) stays fully unrolled: the `bnel` chain at 0x153c-0x157c.
- modelTypeIsRespawnPickup fdiffs with the sizeof bound.

So a sizeof bound is not a reliable LFTR blocker; measure it per loop. Q0765: only a bound held in a variable reliably keeps the counted `slt` loop.
