after a call in an `if` arm changed block structure enough to put `arg0` in `$s3` (`func_80726EE0`); `;`, `{}`, `if (0) {}`, `while (0) {}` did not.

A dead `if` / `do {} while (0)` the permuter inserts before the last statements of one arm usually asks for its own join block: write an `if`/`else` instead of the early return, or a `switch` instead of `if`/`else`, and the block appears naturally (`playerCheckSlopeLaunchArc`, `playerStateRunDecel`). In `textLayoutAppendRows` (112080), two `do {} while (0)` block splits were only compensating for `text = textBuffer` written before a switch whose arms call `_sprintf(textBuffer, ...)`. That early assignment starts the sp+0x6c address web ahead of the calls, the web takes s7, and the u16 loop bound's ucvt spills to 0x54(sp) (+16 bytes). Assigning it after the switch as the for-init (`for (text = textBuffer; *text != 0; text++)`) leaves the web uncoloured and both wrappers go. Before keeping an empty block split that protects a local-array address, try moving the pointer assignment down to its first use after the calls (see also Q0130).
