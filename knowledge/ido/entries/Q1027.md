For M (stack) locals the isvar candidate number is `1501 + 16*vreg_offset` (-4 -> 1437, -8 -> 1373, -10 -> 1341, -14 -> 1277, -20 -> 1181, -24 -> 1117, -28 -> 1053, -32 -> 989); for P (parameter) variables it is `906 + 16*offset`. Declaration position therefore sets the number linearly. 32-bit no-op casts on either side of `==` (unsigned int vs unsigned long, `(s32)`, `(int)`) fold and never put an isop on the local's side.

Evidence: enemyAggroStateUpdate site 97a9f3 (global/12E800.c): a value local of the field's `int` type declared LAST flips the beq to field-first; a `u32` local does not, nor any 8/16-bit local.
