Replacing a raw-offset macro `*(T *)((u8 *)p + off)` with a real struct field can swap `$t0`/`$t9` in an `==` compare (a different candidate numbering, Q0474). Swapping the compare operands in the source restores the target (`effectUpdateAll`, 119370 round 5). Do not keep the macro just for this.

**2026-11-15c refinement:** operand order also depends on array element vs named field. In actorCollisionRunInteractionTable (global/7A510.c, unit "2026-11-15: cleanup HackactorCollisionRunInteractionTable2", b35fbc9e) an `==` between a u8 array element and a CSE'd struct byte puts the CSE'd load on the left when the byte is read as a named field (`bnel t0,t2`) and on the right when the same byte is an element of an array field (`entry->filter[1]` -> `bnel t2,t0`, 0x3bc). Chosen only for that order, the array respelling is a codegen-chosen respelling (Q0816) and stays tagged; it is not a general way to retire puns. For a bare `*p` operand vs a struct field see Q1020.
