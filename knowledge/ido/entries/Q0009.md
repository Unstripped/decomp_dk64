In `func_80026BD8`, `for (j = 0; j < (s32) D_807FC928; j++)` indexing `player[j]` causes IDO 5.3 `uopt` to strength-reduce `j` into a byte offset in `$a1` and compute `max_offset` in `$a2` with a shift/sub sequence (`sll 2; subu; sll 4; subu; sll 4`). However, the compiler still emits the initial loop assignment `j = 0` into `$v0` (`or $v0, $zero, $zero`) and schedules it into the branch delay slot of the preceding function call `jal func_806C96C4`, despite `$v0` being immediately overwritten by the callee's return value.
