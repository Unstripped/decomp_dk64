Same unit/function: a dead `if (d) {}` after the pad loop matters only when it tests d: it keeps the reused counter d live across the pad code, which sets the caller-saved order function-wide (v0/v1/a0 numeric arm 0x718-0x8cc; elen/fneg2 a0/a1/a3); testing any other variable there = no test (154). Hoisting the real `d = '0'` above the pad code also fixes the order (84) but ugen emits li v0,48 before the pad loop (target 0xbc4 after). See also Q0789, Q0895.
