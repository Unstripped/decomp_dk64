In `bossSpawnerUpdate` (src/boss/DAA0.c, merge 80aa79ca), the calls take u8 parameters. Writing `v = (i << 4) & 0xFF; f(v, ...)` does not match. Rewriting it as `i <<= 4; f(i, ...)` gives the exact pair: an `sll` into a coloured temp, then an `andi` into the argument register. No guard or fake kill is needed. The only remaining difference can be the save slot of the value that lives across the call, which ties into the spill-slot ordering in Q0776. A related width rule: if an s32 local is assigned `x & 0xFF` and the call names that variable as a u8 argument, no second `andi` is emitted. If the expression is substituted in at the call (for example through store forwarding, Q0499), the narrowing `andi` is emitted again. So keep the masked value in a named variable at the use when you want only one mask. Evidence: deadsweep full 2 vs 23. Unit "2026-11-15: cleanup HackbossSpawnerUpdate2".
