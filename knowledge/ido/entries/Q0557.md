`textDrawStringVtx` (leftovers revisit 13, matched, five FAKEs removed): (1) `i = count / 4; while (i-- > 0) { ... } count = 0;` keeps the counter a separate variable in a scratch register (as1 renames the division into a ring register) while `count` retains a reference inside the loop that emits no code after induction-variable elimination; uopt still weights it by the loop frequency, which raised count's priority from 30.6 to 51.8 and gave it s8, fixing an s2/s4/s6 callee-saved rotation. `i = count / 4` with count as the counter leaves count near 30, and using count itself gives the wrong `slt`/`beqz` shape. (2) `glyph = &((T *)base)[ch];` instead of `base + ch * 4` means the `ch` widening is no longer shared from the glyph block into a later range check, so ch is reloaded as in the target. (3) `w4 = p->f * 4;` before `w = p->f;` makes the load a coloured candidate and gives `lbu a0; move s3,a0; sll/sra s3`; the reverse order loads straight into the final register. (4) Two temps share a register only across a block boundary: when the target reuses one register for the first and last temps of a straight-line run, the source has a block boundary between them (here a dead `if (w4) {}` tagged FAKE).
