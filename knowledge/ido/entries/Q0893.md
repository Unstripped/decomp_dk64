In `csCmdCameraLookAtMatrixUpdate` (src/global/478F0.c, commit be811a, unit "2026-11-15: cleanup HackcsCondDepositItem"), the only cause of the wrong FP register allocation was a single function-wide web for the `100.0` literal, which has three uses. As Q0333 describes, each use adds 0.5 adjsave, so this web outranks the single-def f32 locals and takes the preferred registers. Giving any one of the three uses its own spelling, so it forms a separate web, produces the target allocation. Which use you split matters only in one case: moving the split to the `rx * 100` use scored 6 instead of matching. So try each use site in turn and do not assume they are interchangeable. If the allocation diff traces back to one repeated float literal, splitting that web should fix it without changing the surrounding code.
