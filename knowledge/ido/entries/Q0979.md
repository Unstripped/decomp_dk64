In `menuHandleHighScoreNameEntryInput` (menu/3E10.c, 0b7fb5, base 085a79), a typed struct pointer built by compound assignment, `entry = table; entry += row; p = &entry->initial0 + col`, produces the target's base-first `addu` and retires a byte-offset cast pun. The forms `entry = &table[row]`, `entry = table + row` and `p = &table[row].initial0 + col` all reverse the operand order, 10 diff rows each. This differs from Q0813, where `entry = p; entry = &entry[i]` still adds the offset first. It means `+=` on a typed pointer is another cast-free way to get base-first order, along with `&p[0] + i` and `(p + i)->f` (Q0816). The lead ruled that splitting the expression is a respelling picked to steer codegen, so the function stays tagged FAKE under the Q0816 precedent.
