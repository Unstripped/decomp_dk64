arcadeInsertHighScore (arcade/0.c) needed an e03dfc steer plus 4 dead-ifs. The target stores a memory-homed local once at entry (`lbu t6` / `sb t6,12(sp)` at 0xa54/0xa68) and has a single PRE-hoisted reload before a loop (`lbu a0,12(sp)` at 0xae0). The load comes from `D_8004A794`, a small .data object that looks unreferenced: 0x20 plus 3 pad bytes, next to another aggregate template, `D_8004A798`. The local is an aggregate initialiser. IDO copies the .data template into the stack object (umov), the aggregate stays a memory variable, and PRE hoists the invariant element load. `u8 initial[1] = {0x20};` gives the same code. While the data is still asm, a 1-byte struct copy (`ArcadeBlankInitial blank = D_8004A794;`) reproduces it. This fixed all fakes (FAKE 5 -> 0). Diagnostic: before keeping address-taken or dead-read steers around a byte in a stack home, look for a template-sized .data object that only this function reads.
