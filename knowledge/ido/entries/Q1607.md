`move a1,a0` (or `a1` holding the switch selector) before a `jal` to a one-parameter callee is not by itself proof that the original passed a second argument: in B2CE0 (behaviourTumbleDebrisUpdate default case, `lbu a0,340(s0)`/`move a1,a0` at 0x7b0/0x7b4 and 0x1d58/0x1d68) the shared one-parameter prototype with one-argument calls matches, so the earlier `// ORIG:` reading was wrong. Test the plain call before tagging a spare argument as ORIG.

Where the spare argument is real (removing it fails fdiff, checked 2026-11-23): BB300 behaviourUpdateContactAndState (selector moves v1 -> a1), B5EC0 actorTrackBoneTowardTarget (FAKE steer), 42630 hudSpawnCountdownTimer (4th argument), every two-argument `slotQueueCancel` call site (FCCD0 K&R owner), `slotQueueGetCountStep(slot, value, shown)`. Same issue: 6AD90 `assetEnsureTableLoaded()` was `assetEnsureTableLoaded(table)` (a0 already held `table`), CC800 `func_800268C0(1, actor)` is the multiplayer overlay's `mpSetFlags(u8)` called with one argument, 450 `transitionStart(mode)` takes one argument. See Q0875.
