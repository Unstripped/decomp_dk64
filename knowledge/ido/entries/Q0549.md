`u8 flags = arg0->unk8C; if (!(flags & 0x20)) { ... arg0->unk8C = flags | 0x20; }` creates two uopt candidates: the variable itself (a store-only unit in the entry block, dead out) and its `ucvt` widening (live from the entry block to the `ori`). The variable is coloured first (v1) and both are live in that block, so v1 is forbidden for the widening, which takes a3; ugen then emits `lbu a3,0x8C(t9)` directly and the dead v1 copy vanishes. Reading the field twice (`arg0->unk8C & 0x20`, `arg0->unk8C |= 0x20`) leaves the byte in v1, and so do dead tests of initialised values (`arg0`/`arg1`/`arg2`, triple forms) or initialising another u8 local: only a v1-coloured interferer live in the entry block moves it. Declaration order matters for the homes: declared before the other u8 local, the frame layout shifted (full 6/33). Matched `modelSlotResolveAssetTextures` (revisit 12), replacing an uninitialised `if (res) {}` that had the same effect.
