HackvehicleUpdateMotion4 (unit "2026-11-16b: cleanup HackvehicleUpdateMotion4", ledger-only ae2477b6), src/global/936B0.c vehicleUpdateMotion (frame/width, extends Q0957 + Q1044(a)/(b)): a u8 local scalar that uopt does not colour (-ve save) still gets its widened lbu PRE-saved to a fresh temp slot (`sw v0,0x2c(sp)`, frame 0x60 -> 0x70; s8/s8 scores 9), so a byte home reloaded with lbu needs a byte that is never a register candidate (array element or address-taken). A `struct { u8 v[2]; }` local is word-aligned like a bare local array. See also Q0919.

**2026-11-16c correction (HackvehicleUpdateMotion5, merge a5af4282):** the widened-lbu temp slot comes from a `!= 0` comparison, not from the u8 local itself. When every test of the u8 scalar is a bare truth test (`if (x)`, `x || y`) it stays a plain byte home reloaded with lbu (isvar M -25/-26 vreg, not coloured) and the frame does not grow: `u8 inWater; u8 onGround;` bare = 0; both `!= 0` 186, inWater `!= 0` only 183, onGround only 146. The array / address-taken workaround is not needed. Same lever: race/6650 raceUpdateRacerMotion's u8 onGround (sb 83(sp), 3 lbu reloads).
