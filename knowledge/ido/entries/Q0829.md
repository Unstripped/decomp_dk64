IDO folds `i * 2 * 2` / `i * 4 + 2` (an element pair indexed through an `s16 *`) differently from `i * sizeof(struct)` plus a field offset, so retyping an element-pair buffer as a struct array (`[i].cell` for `[i * 2 + 1]`) changes code size even though every address is the same. The view is not cosmetic: keep the one that matches.

Evidence: camInitZones / camEvaluateZones (global/201B0.c): the `CamZoneSortEntry *` view takes .text 50512 -> 50480; the s16-pair view (CAM_ZONE_SORT) stays (merge bf83dc8e).
