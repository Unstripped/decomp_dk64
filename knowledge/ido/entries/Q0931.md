In bonusSearchlightSeekGameUpdate (bonus/2690.c), the target passes 1.0 to prototyped f32 parameters as single-precision immediates: `lui a3,0x3f80` for the `sfxPlayOnFreeSlot` argument and `lui a1,0x3f80` for `sfxAllocateChannel`. Writing `1.0` or `1.0f` at those call sites produces an identical object, so cfe folded the double literal to a float constant here and the spelling is not a lever. This narrows Q0847, which saw a rodata double plus run-time `cvt.s.d` for `sfxPlayOnFreeSlot(..., 1.0, ...)` in race/7BD0.c. Do not treat that rule as universal for prototyped argument contexts; check the target for `lui 0x3f80` versus a `ldc1`/`cvt.s.d` pair. In the same function, storing `0.0`/`1.0` into f32 fields was not equivalent to `0.0f`/`1.0f`: the `f` spelling shrank .text by 16 bytes and changed .rodata (Q0473). So literal spelling still matters for stores even when it does not matter for arguments. Unit "2026-11-15: cleanup Polishbonus2690", ledger bfb401b9, base c32f53cb.
