Extends Q0162 (a shared variable used as a call argument sets a register preference) to FP argument registers, with Q1019/Q1451. In bossSpawnerUpdate the x/z locals hold both the light position passed to lightAdd and the case-1 values. Writing the light position as merged repeated expressions keeps the frame and the light block matching, but the case-1 x/z then fall below the conversion temp in priority (2.0 / 1.0 vs 3.0) and lose x's $f12 preference, which comes only from lightAdd's first f32 argument (0xefc/0xfc8). This is register-only evidence that the shared local is needed; it does not meet the ORIG rule, because x/z are never stored to their home slots (0x58/0x54).
