In `raceOpponentBehaviourUpdate` (src/race/0.c, ledger-only 5c8c62b7, base 3144bc00; reconstructed nohit with 3 sites kept), cfe gives all of a function's switch statements ONE shared selector temp. Here that is -72vreg for the case-10, status-0 and status-5 switches, and `projectileRenderSpriteRing` uses -276 the same way. If both switches select on their fields directly, that temp (adjsave 2.33) loses `v0` to the status-0 load cvt (2.67). The cvt also carries the compare-0, the phase store, the temp store and the case-0 `addiu`, and the result is 19 lines off. A user selector variable survives copy propagation into the shared temp only when it has a second definition. The base `u32` selector qualifies because it is re-defined in case 10. `sel0 = unk35; phase = sel0; switch (sel0)` colours `v0`/`v1`/`a0` correctly but emits the copies in the order `move $2,$3; move $4,$2`. as1 then fills the `beqz` delay slot with the phase copy, leaving 4 lines off. An as1probe scan found no record edit that gets below 3. Unit "2026-11-15: cleanup HackraceOpponentBehaviourUpdate3".

**2026-11-15c addendum:** (raceOpponentBehaviourUpdate, unit "2026-11-15: cleanup HackraceOpponentBehaviourUpdate4", 1a78f83f) a dead initializer (`u32 selector = 0;`) is removed before copy propagation and does not count as the second definition (11 lines, same as none); a second definition works only in a block where it is itself a switch selector (the case-10 or status-5 switch). With every steer removed the function differs only by the $v0/$v1 colouring order between cfe's shared switch temp and the field-load candidates (19 lines); single-case switches or default arms on the other unk35 tests do not change it.
