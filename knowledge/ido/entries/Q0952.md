In menuDrawBlinkingPromptText (global/117190.c, kept at dc3c6c), the dead `if (&G && &G && &G) {}` works through one ugen record only. The surviving `beq $4,0,$34` is a conditional jump to the next label, and it is the first record of the block after the early return ($33, 0x11dc). as1 will not copy a branch into a branch-likely delay slot, so the gCurrentMap test at 0x11cc stays `bne t5,at; nop`. Without the guard, as1 emits `bnel` with `lwc1 $f16,52(sp)` in the slot, which leaves an fdiff of 2. Editing t.G shows the mechanism. Deleting both hoisted `la $4,D_80755370` records keeps the full 0, but deleting only the beq gives 2. A 977-edit as1probe scan, which included a plain `b` to the next label, found no improvement. Dead stores inside an if and nested empty ifs vanish in uopt, so they cannot leave that branch behind. Merge 2eb5edb5, ledger 108b5288, base 108db654.
