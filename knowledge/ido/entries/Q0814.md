A value-named f32 local holding a constant (`speed = 0.35f`) used in a double expression keeps the conversion at run time (`lwc1 0.35f; cvt.d.s; mul.d 0.5`), whereas the same f32 literal written inline folds to a double constant in cfe. Such locals reproduce targets that convert at run time; no literal spelling does. The local need not be single-use: one named local used in every place the value appears also matches (uopt propagates it into the f32 uses and keeps the conversion at the f64 use), which makes it a real quantity rather than a FAKE.

Evidence: global/11BC10.c and 119370.c effect updaters (4 sites tagged FAKE, merge eed17d85). Same pass: a typed local for a re-read `void *` slot hoists the load, while IDO keeps the original's reload of effect->allocation after each float store (per-read casts or a typed union member match, Q0759).

Later pass (PolishGlobal11BC10DriftReviews, merge ff294e80): the Downward/Upward drift updaters share one `speed` local for all three axes, retiring 2 FAKEs (director-accepted as a real quantity).
