Within one uopt block, uses that emit no code are removed before adjsave counting: `v *= 1.0f`, `v = v`, `(v - v)` in an expression, a dead copy `x = v` into a local overwritten before any read, and a redundant recompute of v's defining expression (that one kills v's first def and moves its candidate bit). A real second def in the block counts, but computes into v's own register. Confirms Q1438 (Q1049 is the only source of a counted use without code).

So Q1590's extra def/use works only when an existing target instruction takes it (the Q1590 example moved a real countdown onto `near`). When every use of the value is an operand of an instruction the target already has, each extra counted use costs an instruction; `x = c ? f(x) : x` adds a use AND a block (15/5 -> 14/6: lower).

Evidence: bonusSearchlightSeekGameUpdate (bonus/2690.c): honest stickX 1581|0 stays 3.0 under all five code-free uses; a real second def reaches 5.0 but computes the velZ target into $f2 (`add.s $f2` vs `$f8` at 0x5e68). vehicleUpdateMotion (global/936B0.c): waterY/speedY tie 3.0 at 0x1370/0x13b8, 18 speedY respellings in bb 49..53.

Spelling notes from the same run: `0.0f - x` does not fold to `neg.s` (`sub.s` against a hoisted 0.0 in $f14, 0x13c8/0x13d4); these pairs compile identically with the same use counts: `-(a / c) + b` / `b - a / c`, `x / 12` / `x / 12.0f`, `x -= x / 12.0f` / `x = x - x / 12.0f`.
