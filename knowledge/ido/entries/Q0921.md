In healthHudDraw (global/10D2D0.c, 43016c/76bae8) the old version declared an `f32 animParams[22]` local and used only [0], [3], [4] and [21]. That array was faking the spill-temp layout. The target homes 0x94/0xa0/0xa4 are spill temps for hoisted loop-invariant CSE values (`fade*511.0f`, `(f32)centerX`, `(f32)baseY`), and they sit below the area used by declared locals, `_g` blocks and cfe temps (Q0456). The fix writes these expressions inline in the loop and declares an `s16 baseY` in the free -12 halfword. `baseY` matches the original's `(s16)` truncation of `fade*200.0`, a screen y offset. With that change uopt hoists the expressions and reproduces the slots, and scaleX keeps its declared home 0xe8. The x/y assignments inside the call arguments then become plain statements, because they only existed to work around the array layout. The FAKE count dropped from 2 to 0. Rule: if a sparse constant-indexed array's homes look like spill slots, write the values inline and let uopt hoist them. Merge eec7ef5e, ledger b8260f8d, base 9915c291.
