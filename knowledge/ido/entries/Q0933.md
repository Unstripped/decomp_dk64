In `kongChainInit` (global/CC800.c, HackkongChainInit2, merge c2b9ecf2, ledger 07b3a61b; 2d8cdb/313bb1 -> dc42ce, one tagged line, FAKE 2 -> 1), three whole-struct copies of tables read only by this function match as declaration initialisers (`ChainOffsets8 tbl8 = sChainOffsets8;` and so on). They are copied in declaration order to homes tbl8 sp+0x74, tbl11 sp+0x48 and tbl4 sp+0x38, as described in Q0802. The dead `count = 1; n = 4;` stores also match when written as scalar declaration initialisers placed after the struct initialisers: v1=4 lands at 0x768 and a1=tbl4 at 0x7d4. Every switch case overwrites count and n, and the default case returns, so these initialisers are still dead defaults. They are kept only for codegen and are lead-tagged. Q0784 warns that a pre-switch `li` does not prove there was a source store before the switch. Here, the declaration-initialiser form is the spelling that places those dead stores correctly.
