File src/global/19A00.c, scriptOpRemapMotionFrame. 215242 FIXED: the `s16 current` copy is dropped and motion->frameIndex is read inline, as scriptOpUpdateMotionDelta does; there is no store to frameIndex between the reads. FAKE 1 -> 0; 19A00 is 139/139 EXHAUSTED with 0 sites. The director judged it ordinary. 1. CONFIRMS the 2026-11-17f 12E800 compare-order rule (related Q0474, Q0711, Q0690, Q1161): `motion->frameIndex == imm` (imm an address-taken u8) gives uequ{1057 ucvt imm}{906 uilod}, so imm comes first despite its higher number, giving bne a0,v1; `imm == motion->frameIndex` flips it to bne v1,a0. Keeping a variable `current` on one side lets the variable win, which is why the (u32) cast was needed. GENERALISES Q0690 from a global to a struct field: dropping an s16 copy local in favour of inline field reads keeps the one lh (all uses share it) and fixes the compare order.
