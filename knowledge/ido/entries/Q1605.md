A union that overlays a narrow integer on the low part of a wider one (big-endian part view) is not needed when the code only narrows the wide value: IDO emits the same narrow load at the part's offset for the conversion. Verified by full ROM match (issue #1, 2026-11-23):

- `s32` global/field passed to an `s16` parameter: `lh +2` (arcade/0 `gArcadeTexScaleT` → `dlSetTextureScaleAndFlip`, race/0 `RaceCoinConfig.rewardFlag` → `flagGet`, 478F0 `CsOrbitCounters` → `mathSinF`, EFDC0 `param0` → `playerTakeDamage`).
- `s16` field passed to `u8` parameters: `lbu +1` (CB230 spotlight `brightness` → `lightAdd`).
- `u16` field assigned to a `u8` local: `lbu +1` (10D2D0 `healthHudFlags`).
- `s32` table field returned from a `u8` function / passed to `u16`: `lbu +3` / `lhu +2` (CC800 `KongCharacterEntry.characterIndex`, `.model`).
- `s16 *` element `[1]` assigned/returned as `u8`: `lbu 3(p)` (bonus/0, C2A90 `volumeTriggerQueueId[i][1]`).

Prefer the plain wide field and let the prototype/assignment narrow; it is also endian-neutral for ports. Extends Q0594. Not applicable when the narrow part is also written (11BC10 confetti writes `EffectParamPair.lo`).
