In CEAE0 playerUpdateCommon (site 318197), `&gPlayerSlots[i].headX` passed to actorGetNodePos and shared by three call arguments compiles index-first (score 37: idx t7, base t0 vs target base t7, idx t8, addu v0,t7,t0). Any non-leaf base expression gives the load-first add (`(gPlayerSlots + 0)[i]` matches, like the identity cast); leaf spellings (`i[p]`, `p + i`, a slot pointer local, a whole-argument `(f32 *)` cast) do not. The plain `gPlayerSlots[i]` at 0x8a8 in the same function already compiles load-first, so the order depends on how the address is used (a CSE shared by several arguments), not only on how cfe builds the subscript.
