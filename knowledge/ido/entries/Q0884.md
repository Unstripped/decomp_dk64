In global/80150.c `tagBarrelCheckKongFlag` (record 871b3e, cleanup unit "2026-11-15: cleanup HackthrowableBarrelUpdate", merge 373a55e2), declaring the plain locals `s32 found; s32 isSet; s32 value;` and taking only `&value` gives homes 0x28/0x24/0x20. This is the same frame layout as the KongFlagInfo struct. `found` and `isSet` are spilled across calls (`sw v0,0x28(sp)` at 0x7ef8 and `sw v0,0x24(sp)` at 0x7f0c) only because they are live across calls, and declaration order sets their slots. So the frame offsets do not show that a local struct exists. The local-struct/pointer view from Q0457 (`ret = cmp; if (ret != 0) return B;` with `p->` reads) is still needed only for the fall-off return tail, not for the frame. If you use the scalars, still keep the local `s32 flagGet` declaration from Q0743.
