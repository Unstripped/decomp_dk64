Q1122 kept menuHandleControllerSlotInput's reused `bits` (1 << j mask, then the stick bits) untagged because splitting it adds a home and moves the uopt t0 spill 0x44 -> 0x40 at every declaration position. Under the three-part census (rulings.md, ORIG section: frame proof, no-local proof, disjoint same-type roles) that is part 1 only. Part 2 fails: `mask |= 1 << j;` with no local is fdiff 0 (the target computes the bit in a register: `sllv t5,t4,v0` 0x3148, `or a3,a3,t5` 0x315c), so the reuse was a hidden steer; the no-local form replaced it and `bits` keeps only the stick-bit role. Frame evidence for a reuse counts only when no local-free spelling matches.
