flat `s16 tbl[i*2]`/`[i*2+1]` and struct-array `.a`/`.b` emit the same instructions but consume different ugen temps, shifting `t` numbering from that point (`func_806BD7B0`); a field symbol with its own hi/lo (`D_807506D5`) needs a flat `s8` array `[i * 6]`.

The reverse holds for struct fields: rewriting scalar float view fields at PlayerState 0x1C0/0x1CC as `targetScale[0]`/`currentScale[0]` array accesses reorders two float loads (`playerUpdateScaleAndPhysics` keeps the scalar view).

Likewise a byte: reading `Actor.unk155` as the array element `unk155[0]` gives uopt different register candidates than a scalar `u8` field at the same offset (`menuCharacterSelectUpdateActor`).
