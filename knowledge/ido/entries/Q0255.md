a global accessed three times in an epilogue gets its `lda` web coloured and hoisted (`lui/addiu v1; lh 0(v1)`); spelling extra accesses through other already-declared base symbols (`*(s16 *)((u8 *)D_80754F58 + 0x18)`) keeps each `lui/lh` direct.

Why it works (leftovers revisit 13, `mapChunksInitFromMapData`, from uoptinput.c `readnxtinst_searchloop`/`Ustr`): an `lda` candidate is keyed on (symbol, address, size, offset), and global `lod`/`str` are converted to `ilod`/`istr` of an `lda`, so a plain store `G = x;` is an lda use. A store and a loop test of the same global in one block share the web, so the loop's address register starts at the store block (stores via `0(a1)`). A target with symbolic `lui at; sw` stores but a coloured address in the loop needs a different lda node for the stores: spelling them through a neighbour symbol (`*(s32 *)((u8 *)&D_807F6C2C - 0x1C) = ...` for `D_807F6C10`, FAKE, reloc-only) reproduced it byte-exact. Constant-trip loops unroll x4 and peel the remainder as plain symbolic stores with no lda/const candidate (ring `li`); two peeled byte stores share one `lui at` only when the TU defines the array (an extern gives two `lui`s, +1 instruction).
