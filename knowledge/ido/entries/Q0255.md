a global accessed three times in an epilogue gets its `lda` web coloured and hoisted (`lui/addiu v1; lh 0(v1)`); spelling extra accesses through other already-declared base symbols (`*(s16 *)((u8 *)D_80754F58 + 0x18)`) keeps each `lui/lh` direct.

Why it works (corrected 2026-11-07, `mapChunksInitFromMapData`): `uoptinput.c:readnxtinst_searchloop` initially keys an `lda` node on symbol/address/size/offset, but `uoptitab.c:isearchloop` later merges `islda` ichains using only the symbol block number and offset. Different source view sizes or array bounds therefore do not preserve separate address webs. Global `lod`/`str` become `ilod`/`istr` of an `lda`; a store and loop test sharing a global can color that address from the store block onward. A different neighbor symbol for the store keeps it separate (FAKE-tagged); the final match uses distinct neighbor bases for the relocation count and pointer. The cell count instead uses a native function-local volatile static (Q0564). Constant-trip loops unroll x4 and peel the remainder; two peeled byte stores share one `lui at` only when the TU defines the array (Q0565). Normalized instruction-text equality does not prove branch-target equality (Q0566).
