**Resolved 2026-11-07:** `jetpacBonusItemUpdate` matches all 288 instructions without any of its nine dead guards once its actual callback-bearing `JetpacItem D_8002DCEC` is defined in the same C translation unit. The previous acyclic-CFG assumption was false: no backward branch in the final machine code does not imply an acyclic internal as1 CFG. The historical negative results below apply to the incomplete TU, not to all possible C.

as1 marks a symbol address-taken when parsing `.word symbol` (`symbol + 61`, `emit_dword_item` at `0x4593e4`). CFG construction (`func_41dc10`, `0x41dd10`, `0x41e330`) connects every switch `jr` to every address-taken block in the procedure. A same-TU initializer referencing the function therefore adds a false switch-to-entry edge. Entry dominates the switch, so loop detection recognizes this as a natural loop; loop-aware XBB weights and the candidate window (100 instead of 10) replace the DAG model. The late ring-allocated `li t5,2` can then hoist into the timer comparison's load-use stall. These mechanisms are visible in the retained IDO 5.3 as1 recompilation; the C/data reconstruction, not a compiler patch or injected record, passed the ROM gate.

Diagnostic: a scratch same-TU function-pointer initializer changed the reduced score from full 2 to 0, both before/after the function definition and with all nine guards removed. Integration owns only the real 80-byte `D_8002DCE8` color plus `D_8002DCEC` template (`0x9CE8`–`0x9D38`); the callback field at +0x44 is correctly typed as a function pointer. This is an interior data carve, not a TU boundary: `subalign: 8` and `-no-pad-sections` on the two surrounding GNU-as data fragments preserve every address without committing texture data. Whole-file TEXT OK, isolated/local ROM hashes, and 2,468 native-C ASan/UBSan boundary scenarios pass (`db2a5a95`).

Before deriving a scheduling impossibility from disassembly, include same-TU callback data and inspect as1's constructed CFG. An extern declaration does not supply the original address-taken symbol state.

## Historical incomplete-TU investigations

For an **acyclic** as1 CFG, blocks are weighted in number order: a block whose predecessor is already weighted keeps that weight via the copy rule; otherwise each predecessor p gives w(p) - 3 when the block postdominates p, else w(p) + 3 (+1 instead of +3 only when p has a successor outside the loop set). Weights are stored as halfwords, so 1 - 3 wraps to 65534 and back; a first value of 1 counts as unset. A source must satisfy w(src) - w(dst) < 3X + 3 with X = 1. In that DAG, an early-return arm followed by an if without else gives the join w(cmp) + 3 and the store block w(cmp) + 6, excluding its `li` from the compare block's window; Q0548 guards only add same-weight blocks. An `li` also moves only when its def is not live into a successor outside the region and the move saves time (finder `0x42a028`, check `0x429928`). A label between the compare loads and branch, or an inner-loop back edge, brought the target's `li t5,2` into the compare block in record experiments. The missing C producer was the actual same-TU callback initializer, identified above.

Census (2026-11-06, pick-one attempt): `-xbbdbg 31` over 294 of the 304 src C files (the 10 libultra gu/mgu -O3 files were skipped: their phase files use other names; GLOBAL_ASM pragmas dropped, as1 exit codes and the objects vs expected/ not checked; scratch script, not kept) gives 15,829 observed XBB moves; src weight - dst weight is 0 (2,392), 3 (13,229) or 1, 2, 4 (208, inner-loop passes), never >= 6. That is consistent with the window rule for natural CFGs and shows no two-decision hoist among the observed moves; it is not a proof for unobserved code. Moves are appended to the END of the dst block (before its branch); the final local scheduler then puts them in the load-use stall or the delay slot, and one dst can take several moves (hypothesis: the target's `lw t2; li t5; slt; beqz; addiu t3` is two moves into the compare block, the arm's `addiu` and the `li`; unproven). A conditional-branch target block J is a legal source (the arm's `addiu` hoists from the branch-target arm when the layout is swapped), but J's `li t5,2` was never taken in over 20 record variants (li first/last in J, J with `b` instead of `bne`, no `li at`, no competing arm instruction, arm pushed out of the 10-candidate limit): J's scheduled first instruction is the `lw` that feeds its branch, and `.loc` barriers cannot put a ring-later `li` first. A phantom predecessor (record between the arm's `b` and J's label) gives J 65534 and S 65537 = 1, which sorts before the compare block, so it is not a source either; the phantom block appears to take a bb number before the compare block (weights 1, 4, 65534, 1 for bb4-bb7). `while (arg0->unk1C == 1) arg0->unk1C = 2;`, `for (;;) {...; break;}`, `do {} while (0)` and `while (cond) { ...return; }` fold to the natural stream (uopt leaves an unreferenced `lab`, ugen deletes it), so no inner-loop pass exists without a real back edge. On the weight model (itself only partly decoded) every route reduces to one requirement: J must postdominate the compare block (the early-return arm must reach J in as1's CFG) or the store must be reachable from the compare block's level; no C for either is known.

Revisit 13 (R13_sonnet_xhigh_5, park still full 2, every listed idea exhausted): (1) the XBB profitability test uses the real block scheduler; an `li` in a branch-test block already fills the `li at` -> `bne` stall, so a hoist from that block into the compare block never pays (new time == old time). (2) Weight detail: the min over lower-numbered in-loop predecessors is a signed 32-bit compare before the halfword store, so an unreachable block gives its successor -2 = 65534 and deeper blocks wrap upward: an unreachable block never widens the window. (3) The function's uopt `regs` line lists only v0, v1, a0-a3 and s0, and those are removed from ugen's ring globally, so a constant web can never sit in t0-t5: a ring-register `li` proves ugen origin (FIFO ring, Q0554, shows the target's `li t5,2` is allocated after J's `lw`). (4) uopt `dordstore` removes the redundant else-store of `x = c ? k : x`, so the ternary test equals the natural conditional store. Tool: an as1 rebuilt from as1.c with an fprintf at the `func_42a028` call and the time compare builds in ~12 s and prints every XBB decision. No natural CFG gives a weight difference below 6 for this move.

Follow-up (2026-11-07, no match): the final branch-likely delay-slot fill cannot make an earlier XBB move profitable. In IDO 5.3's `traverse_bb`, `do_xbb_opt` runs before the later block walk calling `do_branch_opt` (retained recompilation `.scratch/R13_sonnet_xhigh_5/x3/as1.c:39074,39224`). The latter creates the final `bnel`/copied `lw` delay slot; ugen's conditional emitters use ordinary `beq`/`bne`. Thus the final assembly's occupied branch delay slot is not evidence that the slot was occupied during the XBB profitability test.

The unchanged stage-5 park was tested with state-transition algebra, redundant stores, selective volatile accesses, global-address lifetime guards, false-condition and idempotent transition loops, return-liveness changes, and 12,926 bounded permuter iterations; none produced a full match. IDO 7.1 also retained the misplaced constant and introduced other differences. These are finite negative results, not a proof that no C producer exists; no source or compiler-flag change was retained.
