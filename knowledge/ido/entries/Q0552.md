as1 weights blocks in number order: a block whose predecessor is already weighted keeps that weight via the copy rule; otherwise each predecessor p gives w(p) - 3 when the block postdominates p, else w(p) + 3 (+1 instead of +3 only when p has a successor outside the loop set). Weights are stored as halfwords, so 1 - 3 wraps to 65534 and back; a first value of 1 counts as unset. A source must satisfy w(src) - w(dst) < 3X + 3 with X = 1. After an early-return arm followed by an if without else, dominance forces the join to w(cmp) + 3 and the store block to w(cmp) + 6, so an `li` in that store block can never hoist into the compare block; Q0548 guards only add same-weight blocks. An `li` also moves only when its def is not live into a successor outside the region and the move saves time (finder `0x42a028`, check `0x429928`). Only a label between the compare loads and the branch, or an inner-loop back edge (weights 1, 2, 3), brought the target's `li t5,2` into the compare block of `jetpacBonusItemUpdate` in record experiments; no C producer known (revisit 12).

Census (2026-11-06, pick-one attempt): `-xbbdbg 31` over 294 of the 304 src C files (the 10 libultra gu/mgu -O3 files were skipped: their phase files use other names; GLOBAL_ASM pragmas dropped, as1 exit codes and the objects vs expected/ not checked; scratch script, not kept) gives 15,829 observed XBB moves; src weight - dst weight is 0 (2,392), 3 (13,229) or 1, 2, 4 (208, inner-loop passes), never >= 6. That is consistent with the window rule for natural CFGs and shows no two-decision hoist among the observed moves; it is not a proof for unobserved code. Moves are appended to the END of the dst block (before its branch); the final local scheduler then puts them in the load-use stall or the delay slot, and one dst can take several moves (hypothesis: the target's `lw t2; li t5; slt; beqz; addiu t3` is two moves into the compare block, the arm's `addiu` and the `li`; unproven). A conditional-branch target block J is a legal source (the arm's `addiu` hoists from the branch-target arm when the layout is swapped), but J's `li t5,2` was never taken in over 20 record variants (li first/last in J, J with `b` instead of `bne`, no `li at`, no competing arm instruction, arm pushed out of the 10-candidate limit): J's scheduled first instruction is the `lw` that feeds its branch, and `.loc` barriers cannot put a ring-later `li` first. A phantom predecessor (record between the arm's `b` and J's label) gives J 65534 and S 65537 = 1, which sorts before the compare block, so it is not a source either; the phantom block appears to take a bb number before the compare block (weights 1, 4, 65534, 1 for bb4-bb7). `while (arg0->unk1C == 1) arg0->unk1C = 2;`, `for (;;) {...; break;}`, `do {} while (0)` and `while (cond) { ...return; }` fold to the natural stream (uopt leaves an unreferenced `lab`, ugen deletes it), so no inner-loop pass exists without a real back edge. On the weight model (itself only partly decoded) every route reduces to one requirement: J must postdominate the compare block (the early-return arm must reach J in as1's CFG) or the store must be reachable from the compare block's level; no C for either is known.
