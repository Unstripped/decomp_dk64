Extends Q1038 (`res |= call()` adds a cfe temp that grows the frame; see also Q0450, Q0774, Q0118, Q0550): the cfe temp holding the call result has the callee's return type.

- An `s32` temp takes a word right after the declared locals. It costs frame space only when a uopt expression temp is placed after it; on the older body it sat at the bottom (-44vreg) and cost nothing.
- A `u8` temp is one byte and packs into the word of a `u8` accumulator (-30vreg beside `res` at -29vreg).
- One temp serves the whole function, so any single `|=` creates it.

So when the frame is one word too big around `x |= call()`, check the callee's real return type before adding steers. A byte-returning callee compiles the same declared `u8` or `s32` (Q0774), so its own object does not decide the type.

Evidence: global/36880.c modelSlotResolveAssetTextures (unit CleanmodelSlotResolveAssetTexturesb, merge 361a0c36). Retyping `dlResolveNodeTextures` to return `u8`, with a `u8 result` local, leaves its own object unchanged (`move v0,s3` at 0x5454; an `s32 result` would add `andi v0,s3,0xff`). The caller already stores the result as a byte (`sb v0,43(sp)` at 0xDC). With the retype the cfe temp no longer takes the word above uopt's `head << 3`/`tail << 3` temps, which land at 36(sp)/32(sp) as in the target (`sw t1,36(sp)` at 0xBC, `sw t1,32(sp)` at 0xE4). The frame stays 0x48 instead of 0x50, `res |=` keeps the target's `or v1,v1,v0` (0x104/0x134/0x150), and the two dead-store steers (`head = 0;`, `tail = 0;`, sites cb1852/bb8452) and the size0/size1 locals are gone, fdiff 0. Reusing one count local for head then tail with the `s32` callee scored 42..53.
