In `raceGetRoute`/`raceGetWaypoint` (A960), the target hoists the `items` load above the `D_8002FCF0 == NULL || idx >= count` test. Only `T *e = &D_8002FCF0->items[idx];` at the top, followed by the check and a reassignment `e = &D_8002FCF0->items[idx]; return e;`, reproduces it. Removing the early calculation drops the hoisted load and changes scheduling. No natural spelling was found (plain, diagnose, permute), so it stays a tagged FAKE.
