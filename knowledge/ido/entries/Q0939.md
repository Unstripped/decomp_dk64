In `critterBattleArenaUpdate` (src/critter/5110.c, 28c4ff) the split-label write `D_807FCC44 = 0` was a fake (FAKE 1 -> 0, merge e2ef2623, ledger c7c42721, base 8976068a). Spelling the access through the table made IDO share a single lui/addiu address: the table spelling's `lda` got live range 155 in bb2, with 2 uses, and was coloured `a3`. That sharing happens only within one basic block. The fix was a function-entry `u16 *throwAmmo = &gPlayerInventoryTable[0].throwAmmo`, initialised at its declaration and used for the read, the clear and the 0xFE restore. It keeps a separate lui/%lo pair at each access. The result is RELOC-EQUIV: the `sh zero` relocates against LO16 `gPlayerInventoryTable+0x2f4` where the target has `D_807FCC44+0`. If the same pointer is assigned inside the block instead, the shared web forms again (text 5). The local took pad88's slot (frame -0x90), and no src reference to `D_807FCC44` is left.
