This is a caveat to Q0816, seen while cleaning up `HacksfxUpdateLevelAmbient2` (2026-11-15). Respelling the field access as `(p + i)->f` sets the base-first addu order, but it also changes the frame layout. The pointer local no longer gets its own frame slot, and a later uopt spill home moves up by 8 (0x9c -> 0xa4). Adding dummy locals to win the slot back does not work cleanly. With one extra local the spill home only reaches 0xa0. With two extra locals the frame grows. So when you use the `(p + i)->f` form to fix a regalloc diff, check stack-slot offsets as well. The member form can save a register and still leave the spill homes wrong, and padding locals do not land on the needed +8 offset without growing the frame.
