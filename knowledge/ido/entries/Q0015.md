within one IDO object `_rodata` (strings, jump tables) precedes `_late_rodata` (floats/doubles). A string in `.rodata` at a higher address than another function's `_late_rodata` constant means a new C file starts there; critter's splat-suggested `3340` file is really `3340`/`4040`/`5110` (text boundaries 16-aligned, rodata `0x6170`/`0x6190`). Splitting at the wrong place links fine but shifts `3340.o` rodata and fails the text hash.
