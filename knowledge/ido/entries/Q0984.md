This is a counter-case to Q0026, from the 2026-11-15 cleanup of `HacksfxUpdateLevelAmbient2`. Q0026 says that an `f32` passed in argument slot 3 travels in `$a2` either way, so a `*(s32 *)&field` pun can be dropped. That does not hold when the target writes an `f32` local to its stack home slot and then loads the raw bits back with an integer `lw` into the argument register. That memory round trip is what you get when the source writes `*(s32 *)&local`: cfe takes the local's address, so the local lives in memory and the pun becomes an integer load. A plain `f32` argument would instead give a direct `mfc1` or FPR move. Expected 7130.o, verified at merge, shows `swc1 $f2,0xcc(sp)` at 0x218c and 0x23d0 and `lw a2,0xcc(sp)` at 0x2244 and 0x24fc. Tag the pun ORIG and keep it. Only drop the cast when the target has no swc1/lw pair through the home slot.
