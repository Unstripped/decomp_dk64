A local array initialised from a string literal copies sizeof(array) bytes, not the literal's length. `u8 str[2] = "";` emits one `lhu`/`sh` from the literal although "" is 1 byte. The literal's 8-byte-padded .rodata slot reproduces the 8 zero bytes at the function's literal position (.rodata+0). In textBoxRenderNode this replaced a u16-union copy of a named const template `sTextBoxGlyphStrInit[4] = {0}` (RELOC-EQUIV, symbol dropped from symbol_addrs.us.txt).

Size and position matter. `str[8]` copies with two lw/sw (+0x20 text) and `str[4]` with one lw/sw. Declaring `str[2]` first shifts the slots by 4, and `s32 pad; u8 str[2]` gives t6 and an early `sh`. The match is `Gfx *dl = *gdl; u8 str[2] = "";` plus a trailing `s32 pad`. `""` and `"\0"` compile the same.

This corrects the note in Q1383 that kept the named template.
