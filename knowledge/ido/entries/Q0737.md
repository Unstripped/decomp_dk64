uopt puts the lower-numbered operand of a commutative umpy on the left. In playerStateHoldPickup (global/D5E10.c) an embedded assignment `/(d = 0.15)` renumbers the double constants (3.0 goes 1152 -> 301) and flips the mul.d operands of a different product (trace hp_*.l6).

Corrected 2026-11-14 (HackplayerStateHoldPickup, ledger 8b10b243): the phase is cfe, not uopt numbering. For a commutative FP multiply uopt keeps the operand order cfe emitted. cfe normally evaluates a variable-index subscript (`ixa`) operand before a lighter field chain whatever the source order; when a sibling operand has a side effect (an assignment or a call in the divisor, `/ (baseScale = 0.15)`), cfe evaluates it first (`swp` before `div`) and emits the rest in source order, giving `mul.d $f4,$f18,$f10` at 0x960c. The renumbered constants are a side product; a call divisor shows the same source-order emission. A constant-index member array (`scale[0]`) still counts as lighter. Evidence in `.scratch/HackplayerStateHoldPickup/tr/`. The site stays FAKE.

Corrected 2026-11-15 (HackplayerStateHoldPickup2, merge c0d51059, ledger ba4c85bb): for a commutative FP multiply cfe evaluates the RIGHT operand first whenever it contains an array-element or `*p` load (`arr[idx]`, `arr[2]`, `*parr`, `karr[idx].b`, `(arr+idx)[0]`, `*(arr+idx)`), whatever the left operand is (`arr2[idx]*3.0 * arr[idx]` still swaps). Member loads through a computed pointer (`(p+k)->f`, `p->a->f`), global struct fields and plain variables keep the written order. Only a side effect in a sibling operand at a higher level (the divisor `/(d = 0.15)`) turns the swap off; side effects inside the multiply's operands, or assigning the whole expression, do not. Evidence: `.scratch/HackplayerStateHoldPickup2/t/c*.c`, `probe/D5E10.c` (fdiff 0). Same correction applies to Q0304.

Corrected 2026-11-15 (HackactorScriptedCommandUpdate2, merge 9367a051, ledger 985cee76): the `scale[0]` line above is wrong in general: a constant-index subscript also counts as an array-element load. In `actorScriptedCommandUpdate` (src/global/C4620.c) `sScriptAnimBase[cmd->args[0]] + cmd->args[1]` loads the right-hand `cmd->args[1]` (`lh t3,6(s0)`) before the variable-index table load (case 3, 0x6fc-0x734), which the target needs; retyping the scalar siblings `s16 param1, param2` as `s16 args[2]` retired sites 741d57/e3371e/4119fa/e3371e#2.
