This comes from the 2026-11-15 `sfxUpdateLevelAmbient2` cleanup, in the same unit as the `sfxUpdateLevelAmbient` case. Q0462 describes uopt hoisting a loop's `i = 0` up to the earliest join, and blocking that with a dead store such as `k = 4;`. There is another way to block it. If the 4-trip loop uses an existing local that has no earlier store as its index, the `i = 0` init is not hoisted, so the dead `k = 4` placeholder is not needed. Do not declare a fresh local for the index instead. A fresh local stops the hoist too, but it adds a stack slot and grows the frame, so the match fails. When cleaning up a function that has the dead-store workaround, look for an existing variable that is not live at that point and has no prior store. Reusing it gives clean C and keeps the frame size the same.
