An unused `&param;` or `(void)&param;` statement does not stand in for a dead `void *p = &param;`: cfe drops an address nothing uses, and the parameter stops being memory-resident (42630 csCmdExec 593, the same as removal). A real read through `s16 *id = &param` keeps it memory-resident with its per-iteration reload (uopt folds the address into `lh rN,210(sp)`). Inside a compare, though, uopt orders the indirect `*id` load after the other indirect operand (cutsceneId) whatever the source order (2 rows). A `*id` read at one call argument only matches (0), but it is a redundant alias chosen for codegen, so it is a steer (lead ruling CleanupLead7) and was not applied.
