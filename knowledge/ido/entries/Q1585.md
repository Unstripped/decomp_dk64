In tagBarrelCheckProximityAndFall (global/80150.c) a `volatile u8 spawn` was tagged as needed for the byte width. The real cause is the two `spawn != 0` compares: each makes cfe build a widened ucvt{spawn} copy (uopt cand 27) whose range spans the sqrtf player loop; the variable's leftover short piece then gets adjsave +0.6 and $s0, pushing `triggered` out. Writing both tests bare (`if (spawn)`) compares the variable itself: no ucvt candidate, spawn's pieces get -6.8/-2.0 (the s32 numbers), stay uncoloured, and keep the byte home 0x47(sp) with every sb/lbu (0xb64, 0xbf8/0xbfc, 0xc04, 0xce0/0xce8, 0xd3c, 0xe50). Partial (bare at one test) scores 28/43. A u8 return type with the `!= 0` tests keeps the byte uncoloured but PREs the ucvt copy into a new temp 0x38(sp) (frame 0x48 -> 0x60): only the bare tests remove it. Corrects the byte-width reason given in Q0742/Q0885/Q0191 for this function. tools/variants.py now has a `truth` recipe for this respelling.
