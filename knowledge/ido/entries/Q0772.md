With an s32 `t` and s16 `b`/`c`, `t = a - b; b = t; c = t;` emits one `subu` and two separate sll/sra chains: copy propagation rewrites the first use to cvt(a - b) while the second stays cvt(t), so CSE cannot merge them. Without `b` in the expression (`x = t; c = t;`), or with `t` defined in an earlier block, the two merge into one sign extension; `b = c = a - b` keeps two chains but emits c first.

Evidence: playerCameraUpdateFromTarget (global/8F4B0.c) 0x17ec-0x180c.
