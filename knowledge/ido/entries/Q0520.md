Block-local constants come from the ugen ring (`t2..t9`); a constant in `v0`/`v1`/`a*` means uopt coloured a variable live across blocks (e.g. assigned in both arms, used after the join). uopt never colours `t6..t9`.

Recipe for a target constant in `v0`/`v1` inside one arm: assign it to an existing variable that already owns that register elsewhere, then add a no-code block and a copy-propagation barrier before its use: `d = -100; if (d) {} D_8002D8FC = d | 0;` and `j = 1; if (j) {} D_8002D8F8 = j | 0;` gave `bonusLightFlashGameUpdate` its `li v0,-100` / `li v1,1` (trace: `d` candidate adjsave 2.5 → v0, `j` adjsave 145 → v1; the bare constants were a 0-adjsave web and a negative-adjsave split). Without the dead test or the `| 0` (Q0453) uopt propagates the constant and ugen uses a ring temp. Define the variable inside the arm that used the constant: a definition before the branch colours the same register but as1 schedules the `li` differently. Extra `& 0xFFu` masks on a later expression restored the ugen ring the new pieces had shifted.
