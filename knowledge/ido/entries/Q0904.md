This is the opposite case to Q0601's named pointer local. In `slotQueueAddValue` (src/global/FCCD0.c, merge ec24aa00; fixed in dbac2d/ad98d7), the target computes the element address base + i*stride twice. Block 1 builds it from `v0` right after the call (0x126c). Later blocks build it again from the variable (`a2 = t0 + t2` at 0x12ac). The matching source has no entry pointer local. It only uses `slots[i].field` accesses. uopt copy-propagates the call result `v0` into the first block's address computation and rebuilds the address from the index variable in later blocks. A named entry pointer would be computed once and reused, so the address would not appear twice. When you see this duplicated base+index pattern, write each access as `slots[i].field` and don't add the Q0601 pointer local. Unit "2026-11-15: cleanup HackslotQueueAddValue".
