This came up while cleaning up `enemyGridStateStep` (src/global/C0EE0.c, 2026-11-15). Writing a loop as a pointer walk that starts at an extern array (`p = D` and then advancing `p`) turns the array's `%hi` into one register web. Other loops over the same array (here `D_807FC8C0`) then share that web, so the base register stays live across all of them. To keep the loops separate, compare the pointer against an index-based bound instead. With that change each loop gets its own `%hi` materialization, as the target expects. This was found in the same unit as Q0601, where a named pointer local was the lever. That entry is about intermediate loads, and this one is about how a pointer walk merges address webs across loops. A possible 4x4 `.bss` carve of `D_807FC8C0` was considered but not filed, because there is no evidence that it helps.
