When a constant web steals a variable's callee-saved register, the fix can be on the variable side: move its first assignment later (past unrelated blocks) so its range spans fewer blocks and its adjsave rises above the constant's. This replaces dead `if`s that stretched the constant's range to lower its priority.

Evidence: controllerUpdate (global/F600.c, FAKE 6 -> 2): moving `padIdx = 0` past an unrelated `if (sum != 0x624C9A6C)` raised padIdx's adjsave 7.625 -> 8.714 with no code change (the store sits in the beq delay slot either way), so padIdx was coloured before const 2 (7.786) and three dead ifs went.
