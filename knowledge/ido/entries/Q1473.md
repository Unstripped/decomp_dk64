Static-data unit (2026-11-18, global 0x14CFF0 carve): IDO 4-aligns .data objects (Q0395, Q0913) and pads each TU's .data to 16 bytes (Q1228), so a run of zero bytes that is not explained by an object's own alignment and ends on a 16-aligned address is TU padding. The per-actor-type tables 0x8074AC10-0x8074DA2C have such a pad at both ends (after 7A510's gActorInteractionTable and before 7CA80's first object) and form their own TU between 7A510 and 7CA80 (owner tentatively 7BBD0; 7AF60/7BA00 give the same bytes). The same evidence found jetpac's hidden TU 6E00 (12-byte gaps in .data and .bss) and boot 1630's 16-aligned start at 0x8000DE80 (8 unreferenced zero bytes). data_owners.py RUN lines flag such ends as PAD16.
