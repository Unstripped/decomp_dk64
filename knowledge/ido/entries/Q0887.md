In HackjetpacUpdatePlayerMovement2 (ledger 66af0754), a field read placed where two if-chains meet, with arms before it that store and so kill the field's availability, makes PRE insert one `lw` at the end of each killed arm (0x99c/0x9c4/0x9e0) rather than a single load at the join. A later read of the same field after a second chain behaves the same way: each killed arm gets its own reload, and the untouched path keeps the value in a register (0xa40/0xa9c/0xac8/0xaf8, with v0 carried into 0xb0c). This only happens when the first read's local has a live use. Otherwise the read is removed as dead and the per-arm loads disappear. So when the target shows the same `lw` repeated at the tails of several arms, place one read at the join and give its local a live use.
