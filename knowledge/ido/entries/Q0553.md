## Matched resolution (2026-11-07)

`camPathCommandDispatch` now matches all 1,169 instructions (4,676 bytes), with frame `0xA8`. The earlier negative spelling searches below are historical, not an impossibility result.

1. Decode the low halves as `b = (s16)(arg1 & 0xFFFF)` and `d = (s16)(arg2 & 0xFFFF)`, then store `spA0[1] = b` without the old extra mask. Unlike a cast alone, these expression trees leave the post-call argument pieces uncoloured: the exact `lw t8,172(sp)` and `lw t5,176(sp)` ring reloads appear. The full score initially worsens to 384 while the shape score improves to 1; the remaining register cascade is a separate lifetime problem.
2. Reuse the existing `q` pointer in cases `0x33`, `0x34` and `0x3C` (split the nested `0x34` expression into assignment plus store). It gets the target `v1`, restoring the scratch-ring sequence and reducing the full score to 8. In case `0x19`, compute the absolute-value/clamped index into the existing `s16 node`, then copy it to `sp72`; that gives the target `v0`/`v1` ternary ownership and narrowing, leaving one `lw a1,56(sp)` where the target has `lh a1,58(sp)`.
3. Simply casting that first case-`0x2F` argument to `(s16)d` removes the bare item's argument precolour (Q0508): the raw low-halfword item now takes `t1`, changing hundreds of registers. An always-false `if ((u32)d < 0U) { sfxSetMode(d); }` before the switch restores argument precolouring without emitting a call. Its first argument position preserves the other item's `a1`; using a phantom second argument instead disturbs that allocation. `d` is initialized before the condition, the comparison is false for every `u32`, and the unreachable call has no runtime side effects.
4. The remaining three casts would share one narrowing across calls (extra spill, then `s0` reuse). Spell only the first argument `(s16)(u16)d`, leaving the later two `(s16)d`: all three calls now reload the target signed halfword. Both the unreachable call and the redundant first conversion are FAKE-tagged. Ordinary multiline formatting of the guard and the `node`/`sp72` assignments still matches; no LAYOUT tag is needed.

Verification: unparked whole-file `fdiff` TEXT OK, isolated and local full-ROM hashes OK, and 475 linked-MIPS cases against the prior matching ELF with isolated callees. Cases cover signed-halfword boundaries, optional second/third model calls, auxiliary byte writes, clamped sound indices, command masking and stack/callee-saved preservation. The unreachable hint is trapped if called and was never reached.

## Earlier investigations

Derived from uopt/cfe source on `camPathCommandDispatch` (revisit 12, not matched): (1) uopt splits a parameter's live range at the first call (seed = entry unit, breadth-first search stops at the `cup`); the post-call piece's savings are (uses - 1 reload) / length, so two uses of one load in one block give 1.0 > caller-saved cost 0 and the piece takes the lowest free register (a0/a2). A ring-temp reload (target `lw t8`/`lw t5`) needs at most one use there or all of v0..t5 forbidden; u32/K&R/volatile params, `&param` reads, `x ^ 0`, `register` and dead reassignment all leave it coloured. (2) `spilltemps` (uoptreg2.c) gives every bit in `coloreditems` a slot below cfe's `def Mmt` length in ascending bit order (first = highest address), reusing a slot only for a later bit whose region shares no node, whether or not the item ended up coloured; `-l 4` prints `coloreditems` (incomplete). (3) cfe places `?:` result temps, nested-call result temps and inner-block locals below ALL declared locals, even when created in an earlier initializer; `y = c ? a : b;` as an initializer stores directly without a temp. So no declared array can sit below them.

Revisit 13 (R13_sonnet_xhigh_7, still full 172; registers/sp-masked shape exact except 6 bb1 lines): the target's bottom words 0x38..0x4B are spilltemps ITEMS for the `(s16)` argument expressions (T1 = `(s16)arg1` @0x44, T2 = `(s16)(arg2 >> 16)` @0x3C, T3 = `(s16)arg2` @0x38, the case-0x27 `(u8)T2` reusing a slot @0x48, 0x40 unaccessed), not declared homes; required bit order E_u(`ushr arg1,16`) < T1 < E_a(`a`) < T2 < T3. Writing bb1 as `a = (s16)((u32)arg1 >> 16); spA0[0] = a; b = (s16)arg1; spA0[1] = b; b = (s16)((u32)arg2 >> 16); spA0[2] = b; b = (s16)arg2; spA0[3] = b;` with ONE reused s32 `b` and the same expressions inline in the cases puts T1/T2/T3 on the target slots (frame 0xA8, masked shape 46 vs the park's 96) but orders E_u < E_a < T1 (one slot too many); route kept in `.scratch/R13_sonnet_xhigh_7/camPathCommandDispatch_e11_route.c` (full 490 from colouring). Use sites: `lh` needs a cvtl on top of the item: a named s32 var plus `(s16)` gives `lh`, inline `(s16)(s16)x` folds to `lw`. An inner `{}` block emits no `bgnb` (all locals stay in Mmt block 15). The target colours only v0/v1/a1/a3/t0/s0, so its ring is t1..t9 (Q0418). Masked metric: `.scratch/R13_sonnet_xhigh_7/sd.py <obj> --mask2`.

Second revisit-13 pass (R13_sonnet_xhigh_10, still 172): the corrected item set is E_u = `ushr(arg1,16)` @0x48, T1 @0x44, an unaccessed `ucvt` of the arg2-half chain @0x40, T2 @0x3C, T3 @0x38; the case-0x27 `(u8)T2` item can only reuse E_u's slot (every other holder is used in that case), so `a` must stay a real, un-copy-propagated variable (E_a must not be an item; a child ichain always gets the lower bit, so E_a < E_u is impossible). `find_replacements` (uoptcopy.c) skips copy propagation only when the assigned value has an ilod or is an increment, the variable is non-vreg or in another block while `doingcopy` is off, `no_nested_ops` is set (Q0559), `countvars >= 10`, or the assignment is not in `avin`; no natural spelling of `a` tripped one (`a = (s16)a` after use makes it real but scatters it to t0/memory). The `&arg` variant moves the pieces to t3/t4 rather than giving ring reloads. Batch scorer: `.scratch/R13_sonnet_xhigh_10/h10.py`.
