In `raceSteerTowardTargetWaypoint` (src/race/6650.c, base 66af0754, ledger-only 3854a82b, unit "2026-11-15: cleanup HackraceSteerTowardTargetWaypoint2") the target keeps a `swc1`/`lwc1` store and reload at 0xd64/0xd68. The Q0558 rule (a variable read after its assignment stays a real reload when the rhs contains an `ilod`) did not apply here. The scalar f32 variable's rhs loads `waypointRadius`, but another statement also uses that load. Because the `ilod` is shared, its use count is probably 2 rather than the count 1 the rule needs, so uopt still forwarded the value and dropped the store. Only declaring `f32 waypointThreshold[1]` brought back the store/reload, because array elements are non-vreg and are never forwarded (Q0562). The boundary is that Q0558's reload condition needs an `ilod` that is unique to that rhs. When a load is CSE'd with a nearby statement, use a one-element local array instead.
