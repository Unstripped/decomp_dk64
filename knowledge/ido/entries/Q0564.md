A function-local `static volatile s32` is different from both an extern volatile global and a file-scope static volatile in IDO 5.3 -O2. `in_fsym` lets its Ustr/Ulod remain native Smt accesses; external/global accesses become indirect stores/loads of an lda web. Volatile prevents forwarding the store into the following load. In mapChunksInitFromMapData this gives the independent symbolic `sw t4,...` and `lw a0,...` without an extra address register, and retains the later reloads after calls. A file-scope static did not reproduce it.

The C TU must own the physical storage. This match places the function-static count at the beginning of the 55B20 BSS range (0x807F6C20) and exposes its existing external spelling through undefined_syms.us.txt; other functions really read the same word. This is an explicitly tagged FAKE, not evidence that the original author used this declaration. The count is initialized before every read on the nonempty-map path; the empty-map path never reads it. Neighbor-symbol stores keep the relocation-table pointer/count address webs separate. Header source assignments `off`, `chunkOff`, `base`, `cellsOff`, on separate lines, finish the scheduling. Full ROM hash and 127 isolated linked-MIPS boundary cases passed.
