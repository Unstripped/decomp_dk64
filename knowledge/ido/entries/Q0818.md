`i = 0; do { a[i] = 0; i++; } while (i < 13);` is unrolled into a peeled `[0]` store plus a 4-way loop whose stores run -4..-1 from the advanced pointer (m2c shows it as a comma for-init over the split label of a[1]). Every pre-test form (`for` with s32/u32/s16/u8 i, `!=`, a pointer walker, peeled [0] + for) gives the same unroll with a different store order or 16 bytes less, so the store order identifies the do-while (cf. Q0767).

Evidence: menuInit (menu/3E10.c) clearing D_8076A0D0.
